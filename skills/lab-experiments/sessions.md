# 在 Codex 与 Claude 中持续等实验

共用 [SKILL.md](SKILL.md) 的项目、SSH、清单和告警流程。这里只处理会话工具差异；先看当前会话实际提供的工具。

## Codex

1. 在项目目录执行 `labmon wait -c monitor.toml`；等指定任务时加 `--job 名称`。有 `exec_command` 时使用它，保留返回的 `session_id`。
2. 命令仍运行时，用 `write_stdin` 向同一 session 发送空字符串等待输出，采用工具允许的较长等待（通常30–60秒）。这是读取同一个长轮询进程，不另起进程、不SSH查状态。
3. 有其它独立工作可先做；处理完继续等待原 session。只有进程结束才根据下面的退出码决定后续。
4. 如果工具被 `functions.exec` 包装：外层返回 cell ID 时先用 `functions.wait` 取回结果；内部命令返回 session ID 后才用 `write_stdin`。两种 ID 不能混用。

支持的工具名称随客户端变化，选择实际提供的“执行命令/等待现有进程”能力。没有可持续读取的进程工具时，说明当前会话只能做一次状态核对；不要把脱离会话的 `nohup` 当成自动通知渠道。

等待期间会话保持活动，事件到来后继续处理。用户明确要求结束会话或客户端关闭后，不承诺命令退出会自动唤醒已经结束的 Codex 会话。单次实验等待用现有工具完成，无需创建定时自动化。

## Claude Code

有后台命令和完成通知能力时，将同一 `labmon wait` 作为后台任务启动，保存任务 ID；收到完成通知后读完整输出与退出码，再按同一规则处理。其它 Claude 客户端按实际提供的进程工具选择等待方式。

## 退出后做什么

- **1：新告警。** 逐条读输出。先检查是否含 `archived`：项目已归档就结束监听，不重挂。其余一般告警先重挂同一命令（保留 `--job`），再按 [alerts.md](alerts.md) 处理（`skill_updated` 是 skill 随命令行更新了：重读它列出的几节）；遇到服务不可达、采集停了、同步冲突等持续问题，先按告警说明恢复或退避，不反复启动立即失败的等待。
- **0 / 4：所等任务已有结果。** 0 是全部成功，4 是失败或其它不能继续等待的结果。核对输出后分析结果或修实验；任务等待到此结束。有其它实验仍需监控时再挂相应等待。
- **3：配置、登录或归属等问题。** 按输出解决。不要当成普通告警立即重挂。说“已有另一个会话在挂 labmon wait”或“改由另一个会话等了”的：本会话不再挂 wait，要看状态用 `labmon status`；
  确认那边是本会话续接前挂的（已经停了）、或用户要本会话接手实验时，才用 `labmon wait -c monitor.toml --take` 接手。
- **5：客户端需更新。** 按提示更新后恢复原等待。

项目还有活、15 分钟没有会话来等时，看板上提醒用户（`wait_gone:`，[alerts.md](alerts.md)「看板自己」），所以处理告警前先重挂。

断网时 wait 不退出，自己退避重试，连回来报 `server_back`；连着 1 小时连不上才以 `server_unreachable` 退出，这时告诉用户并马上重挂。

普通查询超时与进程退出不同。`write_stdin` 返回仍在运行就继续等，不重复启动 `labmon wait`。一个项目只让一个会话挂 wait（看板按会话认，别的会话来会被拒），告警才不会被分走；不负责实验的会话（写论文、查资料）不挂 wait，要用 labmon 只查（`labmon status`、`labmon host list`）。

## 压缩、续接与交接

在项目已有的交接记录中简记项目目录、等待命令（含任务名）、已收到未处理的事件，以及尚存的 session/task ID。续接时先核这个进程是否仍可访问；跨会话 ID 可能失效，先核对本机原等待进程并收尾，再重挂，避免留下两份监听。用 `labmon status` 补看当前状态（`labmon check` 末尾另列出这期间页面上的改动），不能只等旧告警再通知一次。

Skill 只提供操作方式，不安装新的守护或唤醒服务。Codex 的技能发现说明见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/build-skills)；具体进程等待能力以当前工具说明和实测为准。
