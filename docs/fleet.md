# 组内服务器

组里别人在用的服务器（管理员视角）：只读地轮探每台实际在跑什么、用了多少，攒下逐小时记录，供分配参考。
在上面动手的只有三件，都由用户定：保活守护（开着守护的那台 GPU 连着空闲就开保活；开、停、重开看板登记的那一个，用户自行开启的保活持续空转、且配置的保活脚本核实了唯一进程组时换成看板保活，见“保活守护”）、
平台操作（页面上点的核对、续租、关机、开机、换人，见下文各节）、借用（用户勾“已和这人说好”后借来拉起 worker、到点自动还，见“借用”；借用中这台进调度，
worker 只在保活真被拉起时暂停拉它的看门狗、还时恢复）。
此外不在上面写文件、不碰进程、不起 worker。组内服务器只给看板管理员查看和操作，通知使用人由管理员自己来。

探针标准输出或标准错误含无效 UTF-8 时，本轮整份结果不采纳，记录该节点的采集错误和字节位置，随后继续轮探其它节点。不会用替换字符改写路径或进程命令；其它 SSH 操作的严格解码保持不变。

## 配置

写在用户级主机清单 `~/.config/labmon/hosts.toml` 的 `[fleet]` 段，改完不用重启服务：

```toml
[fleet]
interval = 600                       # 每台多久探一次（秒）；看板每分钟最多连一台，轮流来
lease_days = 7                       # 平台作业每期天数，从容器启动时间算到期
private_pools = ["pool-private"]   # 组里专用的资源池
private_max = 4                      # 专用池一共几台
public_max = 2                       # 公用池全组最多开几台（多开会被警告甚至强制关机）
keepalive = ["keep_alive"]           # GPU 进程自己的命令行含这些字样就算保活
share = { vram = 0.3, util = 30, cpu = 0.3, mem = 0.3 }   # “可共享”的阈值，见下
keepalive_cmd = "KA_CALLER=labmon-fleet bash /root/data1/alice/keepalive-demo/bin/ka.sh"   # 开保活、让出：后面接 start / running / stop
guard_idle_min = 60                  # 保活守护：GPU 连着空闲这么多分钟就开保活
guard_watch_min = 5                  # 开后在服务器上盯这么多分钟，有别的负载上来就让出（0 是不盯，只靠探测）
port_range = [15151, 15199]          # 开新的时挑端口的范围（可省；须在平台规定的 10000–20000 内）
# me = "ALICE"                         # 旧主机、旧借用没有写人员归属时用的原名字

[[fleet.servers]]                    # 每台一条
id = "29-15158"                     # 跟着这台走：续租不变，换人落在同一节点同一端口也不变（也可单写 keepalive_cmd 覆盖上面的）
holder = "CAROL"                       # 现在的使用人（也是平台作业名）
# job = "CAROL-2"                      # 平台作业名与名字不同时才有：看板换人时同名作业已在跑，加了后缀
ssh = "root@198.51.100.29"
port = 15158
pool = "pool-private"
# guard = true                       # 保活守护开不开（可省：公用池开、专用池关）
# lend = true                        # 入池：空着时借给算力池（持有人在「我的账号」开，见「算力池」）
# lend_hours = "22:00-09:00"         # 入池的时段，每天一段、可跨零点；不写是全天

[[fleet.rules]]                      # 只写例外（可以一条都没有），按顺序取第一条命中的
match = "/root/demo_eval/"                 # 正则，匹配 GPU 进程与各级父进程的命令行、工作目录
kind = "job"                         # job：给它起个好认的名字；keepalive：把它认作保活
label = "demo_eval 评测"                   # 页面上显示的名字（可省，省了用命令简称）
```

管理员用自己的看板账号登录后，人员卡和开机向导里的「我」按账号认：只认账号库里这个账号绑着的组内人员（`users.person_of`，#19），不按同名猜，也不读主机清单。
先登记组内人员，再从此人详情开通看板账号。每个账号对应一名已登记人员，每名人员最多开通一个账号；删账号时绑定随账号一起删。
#70 之前开的账号由 #19 部署后看板服务启动时一次迁进账号库（当时按主机清单 `[fleet.account_people]`、与组内人员同名认出的人，记在记录页）；认不出的迁成不关联。没关联的账号在看板主机用 `labmon user bind <账号> <人员名>` 补。主机清单里的 `[fleet.account_people]` 段迁完就不再读，可以手删。
在「组内服务器 → 人员」打开卡片，可切换「账号与权限」和「服务器与用量」。开通与管理账号只在内网入口（#17），公网入口上「账号与权限」只说一句要从内网管理；登记人员与平台设置按内网权限判断。

换给自己或给自己开新主机时，看板写入 `platform_holder`，续租沿用该主机的作业与归属；自用主机归还后，只在同一人的历史记录里找上次的端口。
换人后复用端口或主机模板，不继承上一人的主机访问名单。新借用在 `borrow_by` 记借用人，命令行按令牌所属账号认；改约定不会变更借用人。
旧主机和旧借用沿用 `[fleet] me` 或旧自用主机作业名的原口径。旧主机第一次写入显式归属时，看板会一并保存原先从作业名推断的人名。已写入的小时用量、平台作业名和共享盘归属继续按原记录读取。

主机清单里写了 `platform_job` 的自用主机也列进来（标“自用”），状态取 worker 的 GPU 进程归属，只算配额，不另外探；
它们也能换人、关机（见下）。

## 探什么

每台每次一条 ssh（复用连接；主机密钥记在状态目录的 `known_hosts`，见下面「主机密钥」），
经标准输入跑 [`labmon/fleet_probe.sh`](../labmon/fleet_probe.sh)。各镜像未必有 Python，所以探针用 bash 写，解析放在本机。它只读：

- GPU 各卡的显存与利用率（5 秒内每 0.5 秒采一次取平均）；
- GPU 进程：`nvidia-smi` 给的是宿主机 PID，经 `/proc/<pid>/sched` 第一行对回容器里的 PID，顺带读工作目录；
- 进程表（PID、父进程、已运行时长、CPU 时间、%CPU、RSS、命令行）；
- 保活进程树各进程的 PSS（`pss` 段，只读保活的，见下面「实际用量」）；
- 容器的内存（cgroup 工作集 = 用量 − 不活跃页缓存；另记收不回的 `anon` = 用量 − 文件页（活跃 + 不活跃页缓存），含 shmem 与内核占用，序列里减去保活记作 `ma`，算给对方留多少用它；保活按 GPU 上的保活进程整棵进程树的 PSS 扣，记作 `mk`，同 worker）、CPU 配额与 5 秒内的实际用量、根盘、容器启动时间。
  探针只送 `memory.stat` 的 `inactive_file`、`active_file`（v1 取 `total_` 项），`fleet.parse` 在本机算，口径同 worker 的 `mem_unevictable`（[worker.md「准入」](worker.md#准入)）；3.10 内核的 v1 没有 `total_shmem`，不能用 rss + shmem；
- `/tmp/labmon-guard.state`：labmon 开的保活是哪个进程组、谁开的、盯到几点、进程出生时钟，后来让出或停掉没有（见“保活守护”）；
- 根盘的文件系统类型与宿主盘的总量（`rootfs` 行，判本地盘测得准不准）、`/dev/shm` 的挂载来源与已用（`shm` 行）；要扫的那次另有开机以来新写的路径（`scan` 段），见下面「本地盘」。

### 主机密钥

labmon 的 ssh 都是 `StrictHostKeyChecking=accept-new`：第一次连自动记下主机密钥，变了照样拒连（`lan.ssh_argv`）。记在哪份文件按这一台定（`fleet._ssh_cmd`，#109）：

- 组内服务器与借来的服务器：状态目录的 `known_hosts`（`overview/fleet/known_hosts`），不动 `~/.ssh/known_hosts`。
- 自用主机：主机清单这台写的 `known_hosts`，没写就是 `~/.ssh/known_hosts`。看板采集、拉起 worker、平台操作里等 ssh 都用它，与实验会话直接 `ssh -p 端口 root@主机` 是同一份。

续租、开机、给自己开回来换了容器时（`fleet.forget`）：关掉连旧容器的复用连接，删掉这一台 host:port 的旧条目（两份都删）；
之后等 ssh 的那次连接按上面那份记下新容器的密钥。这次连接建起的长连接随后被看板与 worker 复用，复用时不再核对密钥，所以记的文件必须是这一份：
以前一律记进状态目录，自用主机续租后 `~/.ssh/known_hosts` 里一直没有新条目，实验会话直接 ssh 被拒（`Host key verification failed`）。

## 怎么归类

每个 GPU 进程沿父进程链往上找“最上层的非 shell 进程”（跳过 bash、tmux、nohup、sshd、VS Code 等），同一个祖先下的进程算一组负载。
每个 GPU 进程依次看：`[[fleet.rules]]` 是否命中它**自己**的命令行 → 自己的命令行是否含 `keepalive` 列的字样（缺省 `keep_alive`）
→ 规则是否命中父进程链或目录；都不中的就是**实验**。
“自己的命令行”里，python 跑的脚本写的是相对路径时（先 `cd` 进目录、用 `train_keep_alive.py`、`./x.py`、`../d/x.py` 起），按它的工作目录还原的完整路径也拿来比一遍（原命令行照旧比）
（`fleet._abs_script`，只做路径规整、不解符号链接；探针的 `script_abs` 同一口径），所以写完整路径的字样与规则也认得相对路径起的同一脚本（#29）。
每人的实验进程千差万别，按规则认不全；能认准的是保活（脚本就那几个），所以只认保活，其余占着 GPU 的都算有人在用，
名字取命令简称（python 取模块或脚本名，带上 `--config` 的文件名）。规则只管例外：起个好认的名字，或者把某个脚本认作保活。
保活认漏了（脚本名里没有 `keep_alive`）会被算成实验：在服务器抽屉“在跑什么”里点那组的“这是保活”，
它的 GPU 进程跑的脚本（照命令行里的写法；python 跑的相对路径写成按工作目录还原的完整路径）就加进 `keepalive`，随后再探一次。GPU 进程是 `python -c`（如 multiprocessing 的子进程）的认不出脚本，要写规则。
**未识别**只剩一种：显卡报出的进程在这台的容器里找不到（多半是同一宿主机上别的容器在用这张卡）。

每组实验还按路径归人（`disk.whose`）：依次看 GPU 进程的工作目录、它自己与各级父进程的命令行，第一个落在共享盘某个一级目录下、
且这个目录归到名单里的人的，就是这人；归属与「共享盘」选项卡同一张表，页面上改了立刻生效。都对不上（如容器本地的 `/root/demo_eval/`）算这台的使用人。
归到的人不是使用人时，卡片上写成“某某 的 …”。
保活字样只看自己的命令行，是因为有人用 `keepalive_guard.sh` 一类的脚本包着真实验，按父进程算会把实验误判为保活。
反过来，同一个守护脚本跑完实验后会拉起保活，这时父进程带着项目路径，所以保活字样排在“规则按父进程命中”之前，
免得纯保活被项目规则算成实验。

一台的状态取最重的那组：实验 > 未识别 > 只有保活 > 空闲（GPU 上没有进程）；自用主机上 labmon 之外的 GPU 进程也算实验；连不上至少两次、持续 150 秒算掉线（`health.link_step`，与工作台主机、项目页同一规则）；刚连不上的隔一分钟再试。
正在做平台操作的服务器（`fleetops.busy()` 列出的：续租、换人、关机、开机、开保活、借来用）不轮探，所以停机那几分钟不会记成掉线；操作自己在开始前、做完后各探一次。
在看板上关了机的服务器不探、不提醒租期、不算配额，页面上标“已关机”。

**实际用量**都去掉保活：显存只算非保活进程的；利用率在只有保活时按 0 算（保活会把利用率顶到 80% 上下）；
CPU 与内存减去保活进程树（GPU 上认作保活的进程与它的子孙，同 worker）的 %CPU（`ps` 给的进程整个生命期的平均）与 PSS。
探针随命令收到认作保活的字样（`[fleet] keepalive`），只读命令行（或还原的脚本完整路径，同上）带这些字样的 GPU 进程与其子孙的 `/proc/<pid>/smaps_rollup`（3.10 内核没有，读 `smaps`），在 `pss` 段送回；
别人的实验进程不读（读整份 `smaps` 要遍历页表、占着对方进程的锁）。按 `[[fleet.rules]]` 认作保活、命令行里没有字样的，探针没读，按 RSS 扣。

**可共享**：实际显存、利用率、CPU、内存都低于 `share` 阈值（显存与内存按占上限的比例，CPU 按占配额的比例，利用率按百分数；内存不算页缓存，与借用的预留同口径，读过大文件留下的缓存收得回、不算在用），
说明这台还能给别人并行用。只记录和显示，不弹通知。

## 保活守护

GPU 长时间没在用（没跑实验也没开保活）的服务器会被平台释放。开着守护的那台，探测见到 GPU 连着空闲满 `guard_idle_min` 分钟（缺省 60），
就 ssh 上去替这人开保活。脚本是 [`labmon/fleet_guard.sh`](../labmon/fleet_guard.sh)，经标准输入送去，只碰保活：

- **开之前**再看一眼 GPU，有任何进程就不开；`ka.sh` 在容器里加了锁，这人同时自己开也不会起两个。正在做平台操作（续租、换人等）的那台不碰。
  `ka.sh running` 的读法与 worker 相同：退出码 0 就是保活在跑，列出的每行是一个进程组；在跑却没列出进程组的认不了归属，不当作没在跑再开一个。
- **开之后**在服务器上起一个后台小循环，盯 `guard_watch_min` 分钟（缺省 5，0 是不盯），每 20 秒看一次 GPU：
  出现不属于这个保活进程组的进程（实验，或这人自己开的保活）就 `ka.sh stop` 让出，保活被别人停了也退出。
  nvidia-smi 给的是宿主机 PID，同探针一样经 `/proc/<pid>/sched` 对回容器里的进程再看进程组；保活本身占几个 GPU 进程都不算别人，对不上的算别人。
  盯完之后靠每次探测：labmon 开的保活还在、GPU 上又有了别的负载，就 ssh 上去停掉它。
- **有实验时让路**：平时只停看板开的保活。看板开启时把进程组与它的出生时钟（`/proc/<pid>/stat` 第 22 项，开机以来的时钟数）记入服务器上的 `/tmp/labmon-guard.state`，停之前核对登记。看板的开、停、重开和远端看门狗共用一把锁。
- **保活空转**：守护开启时，至少两次有效探测相隔 10 分钟或更久、每张 GPU 的有效利用率样本均为零，才考虑恢复。看到其他进程或活动、读不到利用率、换了容器或进程时，重新计时。
  “每张 GPU”是多卡时每一张都要有至少两条明确的零样本，一张卡有活动就不算空转。
  - 看板登记的保活会重开，包括从看板手动开、续租或归还时开出的保活。认身份只比登记里的出生时钟与此刻的，不换算成墙上时钟（时钟跳了照样认得出）；
    11-17 以前的脚本写的登记没有出生时钟，认不出身份，不自动重开（让路、停照旧），下次开保活或换容器后就是新登记。
  - 用户自行开的保活如果仍占用 GPU，且服务器配置的保活脚本能明确确认唯一的进程组，守护会停掉它并开启看板保活。查不清归属时在守护页提醒，同一次空转提示一次。
  - 远端在停之前重新核对容器、保活身份、GPU 利用率与全部 GPU 进程。正在做平台操作时等下次探测，两次实际尝试至少相隔 30 分钟。
  - **停了没开成**：旧的已停、新的没开成时（远端回 `gap`，与“没停成”分开），GPU 上此刻没有保活：记一条并弹通知，下次探测直接再开，
    不等空闲计时与 30 分钟；新登记的进程还在却没占 GPU 的，攒满 10 分钟证据就重开。快速再试只有一次，再不成回到平常节奏。
    换了容器、GPU 上有了负载、借用中或关了守护时不再快速再试。
- **确认开成**：用 `nvidia-smi` 核对保活进程组确实占着 GPU。已有保活进程时直接核对；新启动的进程会等最多约 10 秒，给 GPU 初始化留时间。普通启动遇到已经存在的进程不重开。查不到 GPU 状态或未观察到保活占 GPU 时，进记录与提醒条，连着失败只在第一次弹通知，30 分钟后再试。
- **计时**：有一次没探到（掉线、连不上），或两次探测隔了超过 2.5 个间隔，就从头计时。
  守护只在探完这台后动手；到点后被平台操作或现场复查挡住，会在「保活守护」记录原因和下次再看。同一轮空闲反复遇到同一原因只记一次。
  页面上按上次探测与间隔写“约 07:52 开保活”“约 07:52 再试”。

每台开不开：清单里那台写了 `guard` 就照它，没写的公用池开、专用池关；页面上的开关写进那一台的块。自用主机与借来用的服务器的保活由 worker 管，没有守护
（`guard_state` 给自用主机 `worker`、借用中的 `borrowed`，抽屉里写“保活由 worker 停启”，守护抽屉不列自用主机）。
关掉守护只是不再自动开，已开的保活照样让路。页面上手动“开保活”、续租与换人后的开保活也走这个脚本，同样会让路（记录里写“看板开的”）。

平台的保活按整台算：多卡服务器上只要有一张卡开着保活（或有任务在用），整台就不会被当成闲置。所以 `ka.sh`、`fleet_guard.sh` 都按整台开停一个保活，多卡也不必每张卡都开（用户 11-06 确认）。

### 使用记录

人员卡与服务器卡的占比条、逐小时条都读 `hours/`（`fleetview._parts`、`_stats`），组内服务器与自用主机同一套：

- **借用算给借的人**（Issue #52）：借用中（`fleet.borrowed`）的每次样本除了计进这一小时，还计进 `bw[借的人]`（`fleet.borrower`，读借用时记下的人员名）。
  行的总数照旧是整台的，所以服务器卡的逐小时条与 7 / 30 天统计不变（借出的小时只在悬停里写“借给 某某”）。按人统计时拆成两份：
  借的人那份是 `bw` 里他的计数；主人那份减去它，借出的部分记成“借出”，算进时间占比，不算进实验时利用率与可共享。
  别人用他自己的 labmon 借了这里探着的服务器时，本实例不知道，仍算主人的。
- **自用主机**（`fleetboot.mine` 列出的）每轮全局采集按这一轮的 worker 状态记一次（`fleet.record_mine`、`fleet.from_worker`），口径与探针一致：
  状态只看 GPU 进程（labmon 的任务与容器里找得到的 labmon 之外的 GPU 进程算实验，对不回容器的算未识别，命令行含 `keep_alive` 的算只有保活）；
  只有 CPU 的任务、占位任务不占 GPU，不算实验；利用率是各卡平均、没有实验显存时记 0。保活认的是 worker 的字样（同 `[fleet] keepalive` 的缺省），
  `[fleet] keepalive` 另加的字样与 `[[fleet.rules]]` worker 不认。CPU 与内存取整个容器的（含保活），只用来判可共享。
  本机不在内网、worker 状态过期或停了不记（等同“没探到”），掉线记掉线。`fleetboot.mine` 给平台操作用的状态（有任务在跑就算实验）是另一回事：
  它决定状态标签、续租 / 换人 / 关机要不要勾“可以中断”（与 `fleetops._probe_mine` 同一个），卡片与抽屉里的利用率、显存、“现在”“在跑什么”按样本；样本的各卡带 worker 的吃满程度（`gpus[].busy`，#51），自用主机的利用率因此写近 1 小时平均（[workbench.md「GPU 利用率」](workbench.md#gpu-利用率)）。

  `gpus`、`mem`、CPU 配额、本地盘取 worker 的 `info.rootfs`；没有保活进程树单独的内存与 CPU）。
- **按小时归一**：自用主机每分钟一次、探针约 10 分钟一次，统计时每份计数先除以那一小时整台的样本数再相加，一人几台、借来的一部分小时都按小时算。

## 共享盘

组里各服务器挂的是同一块 NFS（`/root/data1`，1 TiB），每人默认用自己名字的一级目录。这一页回答三件事：谁占得多、最近谁涨得快、还有几天满。
工作台主机页、总览主机表的共享盘条与项目页的“本项目占用”都取这同一份统计，全盘只有一处在扫。

**谁在扫。** 主机清单里写了 `shared` 的自用主机，`labmon worker start` 时把第一个目录交给 worker（`--shared`）。
几台都写了时靠共享盘上的租约（`<worker_home>/disk/lease`）只留一台扫：每分钟续一次，15 分钟没续就由别的主机接着扫，接手时读回已有的索引，不从头来。
扫描在 worker 的一个后台线程里，一次一个单位，不挡调度。

**怎么扫。** NFS 上 `ionice` 不管用，`du` 一遍 50 GiB 要 6 分钟，所以不跑 du，自己数元数据操作限速（每秒最多 200 次 stat 或读目录）：

- **单位**：根下的文件算一个单位，每个一级目录下的文件算一个，二级目录各算一个。一个单位扫超过 20 分钟就停下，以后拆成它的各子目录分别扫。
  登记了清单的项目根（各台 worker 状态里的 `storage.projects`：扫描那台把自己的与 `peers` 读到的别的主机的合起来，#53）连同它在二级以下的各级父目录也这样拆开，
  项目根下的一级目录各成一个单位（项目根本层的文件另算一个），项目里缓存、输出、代码各占多少分得开。拆开在下一次列目录时做（有新的项目根时一分钟内就列），
  与列出的子单位同一次写进索引；只多读几层目录，扫的总量不变。拆开的目录一直留着（与扫得太慢拆开的一样）。
- **列目录**：每 10 分钟列一次一、二级目录（几百次操作），看新建、删除，以及目录自身的修改时刻；目录里新建、删除、改名了文件，它就提前重扫。
- **冷热**：扫完大小或文件数变了（差 1 MiB 以上）的，一小时后再扫；没变的间隔翻倍，最长一周；任何单位两次至少隔上次耗时的 50 倍。
- **节奏**：后台线程一次做一件（列目录或扫一个单位），做完一件 worker 不等下一轮（10 秒）就接着开下一件（主循环每 0.5 秒看一次，`scan_chain`），
  限速按扫描者合起来算：一件接一件时合起来也守每秒 200 次，闲过以后不攒额度。每开一件都先看共享盘慢不慢（`io_yield`），慢就推迟，与拷本地依赖同一个上限。
  耗时由扫描线程自己量（#153 之前记成了收结果的那一轮的间隔，约 10 秒）。索引接连做的时候最多 10 秒写一次（`SCAN_SAVE_S`），手上没活了立刻写。
- **提示**：有清单任务跑完（各主机的用量行，成败都算；扫描那台按 `load_hist` 已读的记录认，近一小时结束的，`Worker.disk_ends`；刚接手租约的那台读进索引后再看一遍近一小时的），它的项目目录下的单位尽快重扫；df 已用比上次对账变了 10 GiB 以上（大文件追加、原地写入，目录修改时刻看不出），
  最近一天有修改的单位提前重扫。扫出错（权限、超时）的一天后再试。
- 每个单位记大小（按占用块数，硬链接只算一次）、文件数、最新修改时刻、按修改时间分龄（7 / 30 / 90 / 365 天）的大小与最大的 10 项。
  索引写在共享盘上的 `<worker_home>/disk/index.json`；看板采集时连同状态一起读回，服务器上的修改时刻没变就不传。

总量与剩余每分钟由 worker 读 statvfs，不用扫；各单位之和与 df 已用的差额在条上画成斜纹的“未统计”（刚开始扫，或扫完以后又变的）。

**归人。** 一级目录按名字对人员名单（不分大小写），对不上的按目录名单列一行，标“目录”；根下的文件归「公共」。
在这人的抽屉里可以把一级目录改归某人或「公共」（`owners.json`）。名单里各人的颜色第一次出现时定下，不随排名变；对不上人的目录画灰色。

**增量。** 每次扫描记一行（单位、时刻、大小，`scans.jsonl`），近 24 小时与 7 天的增量按各单位的扫描记录插值：
一周才扫一次的冷目录不会因为这次扫到了就显得一天涨了很多。新出现的目录从 0 算起，删掉的目录按负的算；
刚拆开、还没列过的目录（扫得太慢的、新登记的项目根；上一份索引里它下面还没有单位）下面的单位是原来那个拆出来的，不从 0 算，拆开与列出子单位分两份索引到看板时也一样；已列过的目录下新建的照常从 0 算（代价是原来空着的目录拆开后第一次新建的漏一次）。

**按项目**（#53）：自己目录下的各单位按 worker 记的项目目录分到项目（`disk._ours`），给主机页的共享盘条、项目页「本项目占用」与项目快照的 `storage`（`disk.project_storage`，[schema.md](schema.md)）。
各项目有合计、近 24 小时与 7 天的增量（含删掉的）、项目根下各一级目录，以及**任务写入量**：近 7 天结束的清单任务（单元申请不算），项目根下此刻在扫的每个单位（拆开以前整个扫的旧单位不算）取开跑前最后一次扫描到跑完那次重扫之差，加起来。
同一段时间本项目别的任务写的也算在里面（记下同期还有几个；用的是同一组扫描的几个任务量出来是同一个数，`bigwrite:` 合成一条），还有单位没重扫的标“等重扫”、满一天按已扫到的算。用量行在任务结束时就写了、重扫在那之后，所以这个数在看板上算，不写进 worker 的用量行。

**告警**（`[fleet.disk]` 里可改 `warn_gb`、`soon_days`、`burst_gb`、`bigwrite_gb`）：

| key | 条件 | 通知 |
|---|---|---|
| `low` | 剩余低于 `warn_gb`（缺省 30 GiB） | 弹 |
| `soon` | 按近 24 小时已用的增长速度（最小二乘）不到 `soon_days`（缺省 3）天就满，且剩余不到 20% | 弹 |
| `burst:<人>` | 这人近 24 小时涨了 `burst_gb`（缺省 30 GiB）以上，且超过剩余的 10% | 弹 |
| `over:<人>` | 这人的占用超过在抽屉里设的提醒线 | 只记进记录、页面标红 |

按人的 `burst:`、`over:` 只给管理员。项目自己的另由项目快照报（`collect._storage`，[workbench.md「告警」](workbench.md#告警)）：`disk:<项目>`（本项目近 24 小时涨得快，门槛与 `burst:` 同一条，两边都给）、
`bigwrite:<任务>:<结束时刻>`（一个任务跑的期间本项目目录净增超过 `bigwrite_gb`，缺省 5 GiB，只给实验会话），`labmon wait` 照常收到。

同一件事恢复以前不重报，都记进记录。页面上是一行四个数（已用与约几天满、近 24 小时与涨得最多的人、近 7 天、90 天没改过的），
一条按人分色的容量条（红线是 `warn_gb`），下面按人列表：占用、24 小时、7 天、近 30 天小曲线、90 天没改过的、文件数、最近修改、多久以前扫的。
按目录名列出的长名字在表格里折行，不把右边几列挤出去；窄屏只留人、占用、24 小时、90 天没改过的、多久以前扫的五列。

**增长的关注档**（页面上算，`diskHeat`）：照近 24 小时与近 7 天（日均）里快的那个速度，算多少天占满剩余；7 天内、或这人的 `burst:` 告警还在，
标紫色「⇈暴涨」（整行左边一道紫线）；30 天内且每天至少涨 1 GiB 标「↑在涨」；24 小时、7 天两个增量跟着标同色。按人列表、人员卡、
人员抽屉的小结与各目录都标，悬停看速度与约几天占满。用自己的紫色，不借告警红与提醒琥珀，带文字与箭头，不只靠颜色。

## 平台与开机参数

开机参数存在状态目录的 `boot.json`，每台一条：作业名、资源池、镜像、端口映射、配置（CPU、内存、硬盘、GPU）、IP、
平台上的作业 id 与创建时间，以及平台“克隆”返回的整份配置（启动命令、挂载卷、规格 id 等）。以后开机、换人时直接按它在平台上重开。
开机参数在各台的抽屉里（收在“开机参数”一节：镜像、来源与时间，展开看全部）；还没存克隆配置的卡上标“开机参数不全”。
每个池最近一份克隆配置是这个池的**模板作业**：开新的时照它的规格、挂载与启动命令提交。

来源有两个：

- **与平台核对**（组内服务器页卡片墙右上角）：登录平台（验证码人输）→ 读作业列表 → 逐台（含自用主机）找运行中的作业（作业名、
  资源池对、端口 22→port；第一页没有就按名字查一次）→ 更新开机参数 → 还没有克隆配置、或作业换过的，补克隆一次（克隆只返回配置，不建作业）→ 汇总。
  全程只读，不停、不提交任何作业。汇总写进 `platform.json`：平台上运行中的作业（预览定作业名时当作占着；labmon 自己关掉的随即删去）、没登记的作业、
  找不到或端口对不上的服务器、公用池超全组上限；镜像、配置与上次不同的记进记录。各池台数不存，页面按登记的服务器与自用主机现算（`fleetview.view` 的 `quota`）。
  最后再读资源池与规格（各规格还空几张卡）、挂载卷，以及人员用到的镜像仓库里有哪些标签，存进 `pools.json`，
  供向导在不连平台时预先核对；这一步没读成只记一条“没读成”，不算核对失败。
- **导入网页上的 Json 文件**：作业详情里“Json 文件”复制下来存成文件，`labmon fleet import <id> <文件>`（核对端口与资源池，对不上不存）。
  它没有启动命令与挂载卷，要与平台核对一次才补齐。

## 本地盘

续租、关机、换人都会重启容器，根盘上开机以来写的（不只 `/tmp`）都会清空。页面在这几处提醒：labmon 之外写的（加容器私有的 `/dev/shm`）到 1 GiB（`LOCAL_ACK`），
续租、关机、换人前要先勾“已和某某说好，本地盘可以清空”（自用主机是“确认本地盘可以清空”；`_risk`，见下面「关机、开机与换人」），确认里写着写了多少、大头在哪几个目录。
数据是 `fleet.local_writes` 合成的 `lw`：组内服务器取探针的根盘与扫出的路径（`server_lw`），自用主机与借来的取 worker 的 `info.rootfs` 与 `storage`（扫法见 [worker.md「本地目录与本地依赖」](worker.md#本地目录与本地依赖)）。

**测不测得准。** 根盘是 overlay、总量比宿主盘小一成以上（平台给的配额，29 是 750 GiB）时，已用就是开机以来写进上层的量；否则（不是 overlay、没配额）已用含镜像自带的，只显示、不提醒、不扫。
`/dev/shm` 挂载来源是 `shm` 的是容器私有的（续租同样清掉），算进去；与宿主共用的 tmpfs不算。

**组内别人的服务器也扫路径**（维护者 11-10 允许，限制写在 [AGENTS.md「只守真会出事的规则」](../AGENTS.md#只守真会出事的规则)）：在平常那次探测里顺带（`scan_due` 定要不要，探针的环境变量 `LABMON_SCAN` 给开机时刻），
走同一条 ssh、同一个探针，结果经标准输出带回本机，不在对方盘上写任何东西：

- `find -xdev` 只读元数据、不读文件内容，`nice -n 19` 加 `ionice -c3`（有的话），限时 60 秒（`SCAN_S`；超时这次记“没扫完”，数字只算扫到的）；
  ctime 早于开机的目录整棵不进（overlay 上开机后写过东西的目录才有新的 ctime），`/proc`、`/sys`、`/dev`、`/run` 不进；只数开机以后新写的文件。
- 在对方机器上用 awk 按前三级目录汇总（四级及以下归到前三级，一、二级目录本层的文件记成 `<目录>/.`，同 worker），只送回前 30 个；本机存前 8 个（`SCAN_TOP`），其余合成“其余几处”。
  没有 GNU find（busybox 等）的写 `nofind`，这个容器不再扫，只显示总量。
- 什么时候扫：根盘测得准、知道开机时刻、开机以来至少写了 64 MiB，且这个容器还没扫过，或根盘已用比上次扫时变了 64 MiB（`WROTE_DRIFT`）；两次至少隔 1 小时（`SCAN_GAP`），
  没扫完的间隔翻倍、最长一天。对方在跑实验照样扫（维护者 11-10 定，#155）。**不扫**：借用中（扫出来的混着我们的）、关机的、点“立即探测”的那次（要快）。
- 结果存在组内状态这台的 `wrote`（`{t, started 那个容器的开机时刻, since, used 扫时的根盘已用（字节）, b, n, top [[路径, 字节, 最近写入]], more [其余几处, 字节], partial, err, fails}`）；
  换了容器（续租、重启）的旧结果不用。

**页面**：组内卡片上过门槛的标一个紫色小标「本地盘 N GiB」（与共享盘的「⇈暴涨」同一套标签 `heatTag`）；服务器抽屉“现在”里本地盘一行是总量条（按配额画，labmon 的缓存与单格临时用项目色，
labmon 之外的按目录一段段斜纹，过门槛变紫），下面「本地盘」一节是按写的总量画的分段条与目录表（大小、最近写入）、扫于多久以前与没扫的原因（`lwBlock`）；
悬停各段看路径、大小、最近写入。自用主机的主机页同一套（资源卡的本地盘一行、记录卡的「本地盘」，[workbench.md「主机页」](workbench.md#主机页hostid)）。

## 续租

组内服务器页卡片墙右上角点“续租”，右侧打开续租抽屉（`#/fleet/renew`，窄屏从底部升起）：一台一行，勾要续的服务器（缺省勾上 24 小时内到期、没在跑实验的），点底部的“续租所选”。
也可以从别处直接开始：页顶租期提醒条上的“续租”（打开同一个抽屉，只勾那一台）；这台抽屉里（自用主机在主机页概况条上也有同一组）的“续租”：在按钮旁弹出确认，只续这一台。
每台下面写着要注意的：在跑实验或有未识别进程（续租会中断它，要在本行另勾“已和某某说好”才能提交）、本地盘开机以来 labmon 之外写了 1 GiB 以上（续租会清空，同样要勾，见「本地盘」）、连不上、还没探过、租期还剩两天以上。“续租所选”灰着时旁边写着原因（没勾服务器、哪几台还要勾确认）。
看板没登录平台时先输验证码（批量续租在抽屉底部输、开始后进度出在抽屉顶上；取验证码时给页面一个 `tok`，提交时带回；别的页面后来又取过验证码的，先取的那张已作废，要重取）；之后：

1. **登录**（已登录就沿用）。
2. **探测并核对**：各台现在再探一次（页面上的状态可能是 10 分钟前的），在跑实验或有未识别进程、本地盘写得多（按最近一次探测与扫出的），而选的时候没确认的，就停下；
   在平台上按名字查作业：运行中的要作业名、资源池对、端口 22→port；克隆配置，作业名与端口对不上就停。
   **这一步有一台不对，哪台都不动。**
3. 逐台（一台续完再动下一台）：
   - **停止旧作业**，等平台上它不再运行。作业已被平台停掉（到期）的跳过这步，克隆同池最近一个同名作业重开；公用池先数全组运行中的服务器，到上限就停。
   - **提交新作业、等运行**：提交克隆出的配置，等平台上出现新的运行中同名作业；开机参数更新为新作业（作业 id、创建时间、克隆配置）。
   - **等 ssh、开保活**：关掉连旧容器的复用连接、删掉旧主机密钥，每 30 秒连一次，连上时记下新密钥（记在哪份见「主机密钥」），再经 `fleet_guard.sh` 开保活
     （已在跑不重开，GPU 上有别的进程不开，开后盯几分钟、有实验上来就让出，同“保活守护”），最后探一次刷新页面。

平台上两步操作之间隔几秒（加随机抖动），等作业停下、跑起来时 20 秒查一次作业列表，最多等 15 分钟（换人从停旧到提交新之间 6 秒一次，见下）。出错就停在那一步，不自动重试；
卡片上写明这一台此刻的状态（平台上什么都没动 / 停止请求已发出 / 旧作业已停、这台不可用 / 新作业已提交 / 新作业已在运行、只差保活），
以及已续完、还没动的服务器。新作业已在运行、只差 ssh 或保活的，等能连上后到这台的抽屉里点“开保活”，不要再续租（会把新作业又停掉）。

## 人员、端口与模板作业

**人员**是一份名单（`people.json`），“人员”选项卡与换人、开机向导共用。名单里每人一份设置：镜像、启动命令、备注。
换人、开新的时就按这份设置提交，没有别的优先级；向导里不能临时换镜像，要换就改这人的设置。设置从哪来写在卡上：

- **从现有作业读的**：占着服务器、名单里还没有的人，与平台核对读到这人现有作业的克隆配置时自动记进名单（只记这一次，之后作业换镜像也不跟着变）。
  还没读到的先列出来，标“还没读到现有作业的镜像”；这时给这人换人或开机，核对行标黄，免得默默用了默认镜像。
- **新的人默认**：“+ 新的人”的表单按新的人默认预填。新的人默认写在“人员”选项卡顶上一行，点「修改默认设置」在按钮旁的浮窗修改（`defaults.json`）；
  没改过就取各台作业里最常见的镜像与启动命令。它只用来预填，改了不影响已在名单里的人。
- **手动设置**：在设置里改过镜像或启动命令的。只改备注不改来源。

卡的顺序：占着服务器的人在前，再按名字首字母（“我”也照这个排，卡上标“我”）。
人员页使用等高卡片。头像是名字的缩写（末尾带数字的取首字母加数字，如 PERSON3 写 P3；多段名取各段首字母，否则取前两个字），
颜色沿用这人在共享盘上的配色。卡面分行标明：「看板账号」一行写角色与需要关注的状态（未开通、已锁定、等设口令等），「服务器」一行写第一台服务器与其余数量，
下面是近 30 天的用量条与实验占比、共享盘用量与提醒。卡上不放操作按钮：点卡片打开详情抽屉，分配一台、修改设置、账号权限都在抽屉里。

- **服务器**：占着的每台一行（状态、GPU 利用率、显存），点一行打开那台的抽屉。
- **近 30 天**：每天一根柱，按状态叠起来（一人多台时一天可超过 24 小时），下面是按服务器的统计（用的日子、有数据的小时、
  借来 / 借出、实验与只有保活的占比、实验时利用率；借来的单列一行“借 某某 的”，已换给别人、已还、已不在清单里的服务器也列着）。
- **共享盘**：这人的各目录（占用、近 24 小时增量、90 天没改过的、最近修改、多久以前扫的；增长的关注档同按人列表；悬停目录名看全名与里面最大的几项；
  长目录名在 `/` 处折行，窄屏目录名独占一行、数字在下面一行），
  一级目录归给谁（缺省按名字，可改给别人或「公共」），以及这人的提醒线。
- **事件**：与这人有关的最近 15 条记录（当时这人占着的服务器上的，以及提到这个名字的），末尾链到记录页。
- **设置**：镜像（与来源）、启动命令、备注，点“修改”就地改。

“分配一台”在这人的抽屉里先列出能分配的服务器（在用的换人、关着的开机、池里有空就开新的），点一台打开那台的抽屉，向导里这人已选好。
「添加组内人员」打开一个新的抽屉，表单按新的人默认预填。所有人（包括自己）是同一套卡和设置。
名单只在工作台里加，不从平台读其他作业名。

**删除**在设置表单右下角（红字“删除这个人”），点了还要再确认。**还占着服务器的人不能删**，那里只写“占着服务器的人不能删”，
要删先把服务器分配给别人或关机。近 30 天用过、已不在名单里的人在选项卡最底下另列一行，点名字看这人的使用记录。
名字也是平台作业名，只能用字母、数字、`_ ~ -`，最多 32 个（平台的规定）。

**作业名**缺省就是名字。同名作业已在平台上运行（比如自己已有 ALICE，又换一台给自己；或给已占一台的人再开一台），
就加后缀 `ALICE-2`、`-3`……，记进那台的 `job`（自用主机记进 `platform_job`）；向导的核对行写明加了后缀。

**端口**按服务器自适应：换人、重开一台时沿用原来的端口；开新的（或原端口被占）时，在 `port_range`（缺省 15151–15199）里
挑最小的空闲端口。空闲指：不是登记的服务器或自用主机在用的，不是平台上运行中、看板没登记的作业占着的（各取一次详情），
并且从本机 TCP 连这个节点的这个端口被拒绝（连得上说明上面还有容器）。向导预览里试连的结果缓存 10 分钟（页面每改一下就取一次预览，不能每次都去连节点的 sshd），
一次最多试 6 个候选（对节点 sshd 连发新连接会被限流），真提交前再探一次。挑出的端口落在平台规定的 10000–20000 内。

## 关机、开机与换人

都要登录平台（已登录就沿用），一次一台。**有一项核对不对，平台上什么都不动**；出错停在那一步，不自动重试。
借来在用的服务器不能续租、关机、换人、开保活（都会停掉自己的 worker），后端直接拒绝，要先在它的「借用」里还掉。

续租、换人、关机三条流程对“这台此刻能不能动”的核对一样（`_risk`）：在跑实验、有未识别的 GPU 进程、没探到（从没探过）、或本地盘开机以来 labmon 之外写了 1 GiB 以上（见「本地盘」）的，都要在页面上勾“已和某某说好”才动，不然停在核对那一步。
自用主机也按同一套（`fleetboot.mine` 把它当成组内的一台）：labmon 之外的 GPU 进程算未识别，worker 没状态算没探到，同样要勾确认；worker 还有任务在跑的拦截在 `_need_ack`：续租勾“可以中断”就行，换人与关机直接拒绝（先在主机页暂停队列）。

- **关机**（这台抽屉里的“关机”，点了先在按钮旁弹出确认）：先探一次，按上面的规则要勾确认；
  在平台上按名字查运行中的作业，作业名、资源池、端口 22→port 都对上才停，等它不再运行。之后 `boot.json` 里这一台记上
  `off`（关机时间、当时的使用人），这台不再探、不提醒租期、不算配额。连不上、平台上也已没有它运行中的作业的，只在看板上标为已关机。
  自用主机关机：停了作业后主机清单里这台标成已归还（`returned`），看板不再连它、不再拉起 worker；要用就在这个池“+ 开新的”选自己。
- **换人**（这台抽屉里的“换人”）：关机和开机连成一步，免得停旧之后这台被组里别人占走。向导在这台的抽屉里：
  点一个人（我 / 工作台，或输新名字）→ 下面一行写核对结果（作业名、端口、镜像与来源、配额；不对的项单独列出，
  没核对上的标黄）→ 一个按钮“停某某，换给某某”。要提交的参数（作业名、镜像与来源、连接、启动命令、挂载）收在“镜像与参数”里，只读。
  开始后：登录 → 核对（探一次旧服务器；找到运行中的旧作业并克隆；数这个池运行中的服务器；定作业名；挑端口；
  连平台核对规格还有空卡、挂载卷属于这个账号、镜像在仓库里）→ 停旧作业（每 6 秒查一次）→ **立刻**提交新作业、等运行
  → 读新作业的 IP 与端口 → 改主机清单与开机参数 → 清旧主机密钥、等 ssh（接成自用主机的，新密钥记进它自己那份，见「主机密钥」）、开保活。做完页面上给出连接命令（可复制），发给新的人。
  主机清单这样改：同一节点同一端口只改 `holder`（与 `job`），否则新加一台、删掉旧服务器。
  - **换给自己**：组内服务器里这台去掉，主机清单加一台自用主机（照抄现有的自用主机，连同 worker、保活检查，改 id、ssh、端口、
    `platform_job`、`platform_pool`；同一 ssh 与端口有已归还的自用主机就恢复它），看板下一轮采集拉起 worker。
    新的这台还没有登记、上一台（同池最近归还的自用主机）上留着登记的，结果后面提示到主机页接上（[workbench.md「搬、移除队列登记」](workbench.md#搬移除队列登记)）；开机给自己的同样。
  - **自己的服务器换给别人**：worker 有任务在跑就不动（先在主机页暂停队列）；停了作业后这台自用主机标成已归还，组内服务器加一台给新的人。
- **开机**：关了机的卡右下角、这台抽屉里的“开机”，以及每组末尾的“+ 开新的”。重开一台缺省还给原来的人，可换人；
  用这台自己的克隆配置，没有就用这个池的模板作业。开新的选池与人，端口自动挑：这人在这个池里上次关掉的那台（组内服务器、自己已归还的自用主机）的端口优先沿用，
  被占了才挑 `port_range` 里最小的空闲端口（`fleetboot.back_port`；说明里写“上次的端口 X 被占，改用 Y”，接替原来那台时写“原端口”，预览与真操作同一句，`fleetboot.pick_port`），这人本机的 ssh 配置不用改；池满了组标题标“已满”，不再显示“+ 开新的”。
  自用主机都关了（已归还）时，平台账号与自己的名字照样从已归还的那一块取，给自己开新的照常登录、接成自用主机；端口与节点同已归还的那块时恢复那一块（预览写“恢复已归还的自用主机 X”），否则照抄一台加上。
  提交以后与换人相同：等运行、登记新服务器、等 ssh、开保活。新作业落在哪个节点按平台给的内网 IP 换算（192.0.2.x ↔ 本机连的 198.51.100.x）。

停旧以后提交被平台拒了（明说没收）的，这台已标为关机，可以直接点“开机”重开；页面上写明这台此刻的状态。

**开保活**（这台抽屉里的按钮，不碰平台、不用验证码）：先探一次，在跑实验或有未识别进程就不开（免得和它抢 GPU）；
上次探测报主机密钥变了（在网页上续租或重启过）的，先删掉旧密钥再连。确认保活已占 GPU 后才显示成功。

## 借用

组里别人的服务器空着、或对方只是轻用时，说好后借来给自己的项目跑（[`labmon/borrow.py`](../labmon/borrow.py)）。这台抽屉里的“借来用”（在按钮旁弹出表单）：
勾给哪些项目用（不勾是自己的项目都能用）、约定还的时间（可选“不约定”），勾“已和某某说好”；对方在轻用的还有一个“某某在轻用（…），也借”，缺省勾上。
约定还的时间精确到分（`whenPick`，Issue #26）：日期框（`type=date`）加时、分两个下拉（分按 5 分钟一档，已有的约定不在档上时另列它那一分；不用 `datetime-local`，有的浏览器里它只弹日期、时分要手打）。下面一排小签：“现在”、+1 小时、+3 小时、+1 天、+3 天、“不约定”；+ 在当前选的时刻上往后加，可连点（点两次 +1 天就是两天后；当前的已经过去时从现在加），“现在”回到现在。只改了日期或时分中的一段而别的空着时，空着的从现在补上。
借来用的缺省是现在（下一个 5 分钟档），这时说明行写“请选一个将来的时刻”（不标红），直接点“借来用”会拦下并标红：要么往后加、改时刻，要么点“不约定”；改约定的缺省是现在的约定（没约定的仍是不约定）。
再下面一句“到几点，还有多久”（今天的只写时分），晚于对方租期截止（到期前 1 小时）的加一句按租期截止。
已经过去的、日期只填了一半的，控件与这句标红，点“借来用”“保存”时拦下（只填一半不会当成不约定）；服务端也拒绝已经过去的（`config.check_future`）。
表单里写着给对方留的量。不碰平台，作业与租期还是对方的。借用中这台的用量算给借的人（人员卡上主人那边是“借出”，见“使用记录”）。

- **借来**：先探一次，对方要么空着（GPU 上没有进程或只有 `ka.sh` 管的保活；worker 要卡时会停它，ka.sh 停不了的保活要对方先停），
  要么轻用（`borrow.using` 说对方在用什么：GPU 上的实验、VS Code、终端；`fleet.analyze` 的 `share` 判为轻用，即除保活外显存、利用率、CPU、内存都低于阈值；
  `borrow.can_borrow`），轻用的要勾“也借”。
  再在一条 ssh 里看共享盘与 Python 在不在，同时逐个核对认作保活的 GPU 进程（`fleet.analyze` 每组负载的 `gpids`）：`fleet_guard.sh` 的只读动作 `kacheck`
  （不拿锁、不写文件）看它所在的进程组在不在 `ka.sh running` 列出的里面，一个不在就借不了，提示写明那个进程的命令行、PID、工作目录，请对方停掉、要保活改用 `ka.sh start` 开；
  ka.sh 本身出错（跑不起来、输出认不出）另写一句，带上退出码与它的报错（#29：以前只看 `ka.sh running` 的退出码，认出一个就放过旁边停不了的，提示里也没写是哪个）。
  ka.sh 认保活的规则：python 跑它的保活脚本（`ka.env` 的 `AGRI_KA_DIR/AGRI_KA_SCRIPT`），命令行写完整路径，或相对路径按进程工作目录还原后是它（维护者 11-17 定，#29），worker 的 `ka_owned` 同一条。
  然后这台的块里写 `borrow_since`、`borrow_until`、`borrow_for`，下临时指令、拉起 worker。
  借用中它同时是调度主机（`config.guest_host`：id 不变，照抄一台在用自用主机的 Python、共享盘、worker 目录（显式配了 `worker_home` 的照用）、检查项，主机密钥沿用这里的 `known_hosts`），
  侧栏里多一台“27（借 BOB）”。不在对方的容器里扫共享盘。
  worker 一起来就找一遍保活看门狗（会把 worker 停掉的保活又拉起来的进程），只列出来（确定的写明“要卡时它把保活拉起来就暂停，还卡时恢复”）；真把保活拉起来了才暂停确定的（它正持着平时不持的文件锁时等它放了再暂停），规则见 [worker.md「保活」](worker.md#保活)。
  出借方自己的保活管理器（如 BOB 的 `keepalive_control.py`）也按这条规则，不调用它的让路接口，见同一节。
  借来时 GPU 上的保活是 labmon 自己开的（上次归还时守护式开的那个，`/tmp/labmon-guard.state` 里登记着）不算对方的，别的都记成对方的（`borrow.json` 的 `ka`，归还时不停它）。
  这和 worker 停不停得了是两回事：对方的保活只要是 `ka.sh` 管的，worker 要卡时照样停；停不下来时（`ka.sh stop` 一直失败）worker 记事件、工作台告警，状态行改写没停成的原因（[worker.md「停不下来」](worker.md#保活)，#102），归还结果里也写一句。借用中对方另起的、`ka.sh` 停不了的保活：那张卡不放新任务，记事件请对方停；它的内存与核数不算对方的用量（与给对方算预留的样本同口径，别的卡照放），核数另从可用量里扣（#37，[worker.md](worker.md#借来的主机给对方留余量)）。
  页面上点的借来用和别的组内操作一样在后台跑（`fleetops.run_borrow`），抽屉顶上逐步显示进度（探一次、查共享盘与 Python、写清单下指令、
  拉起 worker 等它报到，约半分钟），借不了就停在那一步写明原因；同一时间只做一件组内操作。命令行的 `labmon borrow` 直接做完再返回。
- **约定时间**（精确到分；主机清单里写 `YYYY-MM-DD HH:MM`，以前只写日期的取当天结束）：`borrow_until` 与对方租期到期前 1 小时取早的，worker 的 `deadline` 指令（目标 `borrow`）按它准入：之前跑不完的不放，没估时的照常放；
  到点不停正在跑的，跑完自动归还。提前 2 小时、到点、超时 1 小时各提醒一次，前两次附上排着、约定前跑不完的任务数（`borrow.late_jobs`）；
  这样的车道项目看板另报 `borrow_cut:<车道>`，到点之后、归还之前一直报（到点追加的 drain 排在约定的 deadline 后面，挡住它的仍是约定），叫醒实验会话换主机，截止是约定时间时也可请用户延长约定，取的是对方租期时延长推不迟、不这么提（这句由 `borrow.late_do` 生成；[workbench.md「告警」](workbench.md#告警)）；抽屉里与这台的主机页概况条上都有“改约定”“跑完就还”“现在停”（按各自的停法停下；`borrowBtns`）。
  改约定的表单与后两个的确认都在按钮旁的弹窗里（`popConfirm`）；正在停下（点了现在停）的不再出按钮。
- **撤销还**：“跑完就还”在还掉之前可以撤销（`borrow.cancel_return`；按钮换成“撤销还”，命令行 `labmon host restore <id>`）：
  撤掉要还时下的 drain、清掉要还标记，照常放新任务。过了约定时间的撤不了（下一轮又会要还），先改约定到更晚再撤；要还期间也能改约定。
  “现在停”不能撤（正在跑的已经停了）。采集这一轮中途撤销的，合并状态时按撤销时刻 `kept` 不把本轮读到的要还写回。
- **给对方留的量**（`borrow.reserve_for`，借鉴 Kubernetes VPA recommender）：组内探测近 7 天里对方空着或轻用（`sh`）时的样本、对方的实际用量（除保活；内存取不算页缓存的 `ma`，保活按整棵进程树的 PSS 扣，与 worker 比的同口径）。
  不带 `mk` 的旧样本（#29 修复部署前）的 `ma` 扣的是保活进程树的 RSS 合计：父子进程共享的页重复相加，扣多了（27-15152 上约 2 GiB），预留跟着偏低；这些行改取不扣保活的总 anon（`ma` + 当时扣的 `m − mr`），偏向多留，11-17 后七天内全是新样本，回退删掉。
  只取轻用时的：借卡只在对方轻用时借，留的是轻用的余量，对方回来跑大实验就是超出预留。借用中的样本带 `bw`，不算（正在借的这次也按 `borrow_since` 排除）；
  按时间衰减加权（半衰期 1 天）取 95 分位再乘 1.15，下限显存 2 GiB、内存 4 GiB、CPU 1 核；按小时缓存。组内页的数据里借得了的服务器带着它（`reserve`）与 `using`。
  看板把它随 `guest` 指令下发（`keep`），差 10% 以上就重下。`hold`：借来时对方在轻用（这台的块里记 `borrow_light`），worker 准入时预先扣掉它；
  借来时对方空着的不扣（这段时间没人一起跑），对方回来用时有了这人 GPU 进程的卡算超出，内存、CPU 仍按推荐量判断。借用中对方被挤到一次（worker 报的被挤掉的任务、或我们没有任务在跑时内核杀了 labmon 之外的进程），
  这次借用的预留乘 1.2（最多 3 倍），记在 `borrow.json` 的 `bump`，提醒一次（`borrow_hit`）。显存是整台合计，worker 按“对方的卡”留（单卡就是它；多卡是 0 号卡与对方有进程的卡）。
- **对方说好不用**（Issue #30）：借来用与改约定的弹窗里勾“某某说好约定时间前不用：不给这人留余量，空着的都能用”（缺省不勾；选了“不约定”时灰掉，说好不用要有个时限）。
  这台的块里记 `borrow_away`（取约定时间；改约定时按勾选框重写，不勾就去掉；再借时重写），看板随 `guest` 指令的 `keep` 下发 `away`（还没到才带）。
  到那时以前 worker 不预先留（卡、内存、CPU），对方此刻占着的照算在可用量外（VS Code 之类的常驻进程），对方的内存、CPU 超过推荐量也不整台不放；规则见 [worker.md「借来的主机给对方留余量」](worker.md#借来的主机给对方留余量)。
  对方有了新的 GPU 进程（连着两轮；说好不用开始时已有的不算）、或我们没有任务进程在跑时内核杀了 labmon 之外的进程，就当对方回来了：worker 立刻按普通规则（借来时对方在轻用的重新预留），状态里写 `guest.away.end`；
  看板清掉 `borrow_away`、重下不带 `away` 的指令，按 `borrow_back` 提醒一次（wait 报 `borrow_back:<主机>:away`；正在跑的照常跑完，不自动要还，要不要还和对方商量）；要再开得在改约定里重新勾。
  借用中的探测样本带 `bw`，说好不用的时段不进 `reserve_for` 的历史。命令行 `labmon borrow <id> --until … --away`。
- **对方用得比预留多**：worker 的规则（见 [worker.md「借来的主机给对方留余量」](worker.md#借来的主机给对方留余量)）：那张卡（内存、CPU 超出时整台）不放新任务，回到预留以内 10 分钟后恢复；
  正在跑的照常跑完（停了白跑），快撞上限时再提醒一次，要不要停由用户线下和对方商量；我们的任务真撞上容器内存上限时先被杀、重新排队。看板各提醒一次（`borrow_back`）。独占任务等对方用完才放行（不留卡、不堵别的任务），被打扰就作废重排（所有主机一样）。
- **归还**（`borrow.finish`，不重启容器）：一条 ssh 停 worker、停掉还挂着的占位任务、清掉 `/tmp/labmon` 与这台的临时指令；
  借用期间 `/tmp/labmon` 之外新写的（worker 从借来时算起，见「本地盘」）不动，留在对方那边、我们拿不到：“跑完就还”“现在停”的确认与归还的结果里列出来，要留的先挪到共享盘；对方原有的不在这里列（续租对方的服务器时才列）。借来时 GPU 上没有保活的（`borrow.json` 的 `ka` 为假）顺手 `ka.sh stop` 停掉 worker 开的保活，
  借来时就有对方保活的不碰、不重开（worker 要卡时停过的话，空闲时已按同一个脚本开回来），结果里写“保活还在（借来时就在、是某某的，归还不停它）”，借用期间 worker 停不了它的另写一句原因（worker 状态的 `keepalive.stuck`）；块里写 `borrow_returned`；再按守护的方式开保活（`ka_start`：已在跑不重开，开了就盯着、对方的实验上来就让出），然后恢复借来时暂停的看门狗（它醒来看到保活在，就不会再拉一个），
  随即探一次；通知“可以告诉某某了”。
- 借用中这台照常探测与统计，保活守护不管它，续租、换人、关机、开保活按钮收起，后端也拒绝（都会停掉自己的 worker），要先还。
- 实验会话经 `labmon wait` 知道：借到（`borrow:<id>`，只报给能用它的项目）、约定前跑不完不会再放（`borrow_cut:<车道>`，项目看板的告警）、到了约定时间、对方用得比预留多、已归还（一天内）；被挤掉重排的任务经 `void:`。
- 项目页上：顶栏与资源组里这台的名字后面有借用小标签（`borrowBadge`：到几点、跑完就还；对方在用、过了约定时间标红，悬停是完整说明），
  小图与时间线里叫“借 BOB”（`hostShort`）。已还、上面的任务都跑完了的主机收成顶栏的“已还 N 台”。

平台作业换成自己的（“换人”换给自己）是另一种借法：成了自用主机，能续租。要约定还的时间用 `labmon borrow <主机> --until … --from <名字>`
（写进 `[[hosts]]` 的 `borrow_until`、`borrow_from`），准入一样，到时只提醒，换回去还是“换人”。

借卡的几条决定（用户 11-06 定，设计时按它们来）：对方轻用时也可借，弹窗里“对方在轻用、已说好”缺省勾上；撞上容器内存上限时先牺牲我们的任务（`oom_score_adj`），保住对方的体验；
给对方留的量按对方历史用量推荐，不用固定数；“留卡给对方”按卡，只对多卡有意义（现在组内每台一张卡，以后可能多卡）。
以后要做真正的组内服务器共享（多人同机、对方优先、借出与收回），借卡的抽象按共享的概念来做：让路、预留、按卡。

## 算力池

组里各人把空着的组内服务器借给全组，组里人把清单交给池、由看板放到这些服务器上跑（#13）。池按借用的推广来做，复用借用、worker 调度与清单登记，不另起一套（[`labmon/pool.py`](../labmon/pool.py)）。
这一节写清单怎么交、服务器怎么入池（B，#24），看板怎么自动借、放、还与收回（C，#25），自用主机怎么入池（#79）。

- **入池**：`[[fleet.servers]]` 里的 `lend`（开没开）与 `lend_hours`（每天一段 `HH:MM-HH:MM`，可跨零点，起止相同或不写是全天；`fleet.lend_span` 解析、`fleet.conf` 校验，此刻在不在时段里 `fleet.lend_open`）。
  持有人本人在「我的账号 → 概览 → 我的服务器」开关、改时段；管理员在这台的抽屉里「算力池」那一行代开，要能做平台操作、勾「已和这人说好」（代关不用勾）。
  都经 `POST /api/pool/lend`（`pool.set_lend`，记一条配置改动）。换人时（`config.set_fleet_holder`）这两行一并去掉：新持有人没同意过。组内卡片上入池的标「入池」。
- **成员**：管理员，或账号对应的人（`users.person_of`）有一台开了入池的组内服务器或自用主机（`pool.member`，不看此刻在不在时段；自用主机要能入池，见下面「自用主机入池」）。成员才能往池里交清单（`users.may_host` 对 `pool` 问它）。
- **交清单**：`labmon worker add pool ROOT JOBS --project P`。`pool` 是保留的主机 id（`config.POOL`，`[[hosts]]` 与组内服务器都不许叫它），
  登记落在自用主机那份 worker 目录（`config.pool_home`：借来的主机照抄的那台，`config.guest_host` 同一个模板）的 `hosts/pool/queues/`，
  经与它共用 worker 目录的在用主机代办（`workerctl.via`）。池里的清单要停得下来、换得了台：不许 `--stop boundary`、`--gpus`、成组（`gang=`）与占位任务，停法缺省 `term`（`labmon_worker.pool_refuse`）。
  一条清单只归一台照旧：之后 `worker add <自用主机> …` 把它从池里搬回来。撤回 `labmon worker rm pool ROOT JOBS`（在清单此刻登记的地方撤，`pool.locate`）；`worker status|start|stop pool` 都不认。
- **看得到**：全局快照的 `regs` 里 `host` 为 `pool`、`state` 为 `pool` 的一项（在用主机之后、已归还的之前；`added_t` 是登记文件的修改时刻）；
  项目页有池车道（`collect._lane` 标 `pool`，没有 worker 管：不报队列进程不在，等待原因“在算力池里等着放到某台”接上 `pool.lists` 的 `why`，`pool_since` 是开始等的时刻），车道经同一 worker 目录的在用主机代读，代读的那台不是本项目的主机时不进项目快照。
  算力池不是主机（#89）：时间线不画它一行，待放的清单在时间线下面一条一行写原因与已等多久，「运行中」与车道悬停里同一句；顶栏只在有待放的清单时写「算力池里待放 N 条清单」，资源小图不画它；车道名不把它算进几台主机，池车道前面总写「算力池」。
  刚从池借来的主机搬回池里、那台手上那一格还在跑的（状态目录 `current` 里放行的主机是那台）在池车道上照样算在跑（探针按 #95 的口径认，#78）。
  别处 `after=` 等池里的任务算还会跑（worker 的 `Worker.pool_todo` 随 `peers` 读进 `peer_todo`），不报找不到。

### 自动借、放、还（#25）

工作台每轮采集（只在持有服务租约的那台）里，`borrow.check` 之后、快照写盘之前跑一次 `pool.tick`：先还、再放、最后借。结果进全局快照的 `pool`（各待放清单从何时起等、为什么还没放）。

- **还**（`pool._returns`，都经 `borrow.request_return`：不再放新的池任务，在跑的跑完就还、开保活）：
  - 主人回来：worker 状态的 `guest.owner` 非空（对方超出预留的几项，去掉只因 ka.sh 停不了的保活超出的卡；再加上有了对方 GPU 进程的卡，预留以内也算：池借只在 GPU 空着时借）。池借来的主机上 guest 指令带 `keep.pool`，worker 对主人回来的这台整台不放（`guest_block`），看板同一轮要还。
  - 关了入池，或此刻不在入池时段里。时段结束、主人租期截止由借用的约定时间照旧管（`borrow.until` 取时段结束，`borrow.cutoff` 与租期前 1 小时取早）。
  - 连着 15 分钟（`POOL_IDLE_S`）没有池任务在跑（占位不算）：从借来、最近一次有池任务在跑、最近一次往这台放清单（`borrow.json` 的 `pool.placed`）里取晚的起算，刚放上来、队首还没开跑的不会放完马上还（#80）。借来后一个也没跑起来的，记下这个形状（卡数、单卡显存），24 小时内不再为它借这台。
  - 换了容器（借来之后的组内探测看到的容器启动时刻比借来时 `begin` 现场探到的晚：主人续租或重启了；借来之前的探测不算）：旧容器里的 worker 与任务都没了，直接 `borrow.finish(gone=True)`，只停 labmon 的 worker（按命令行核对 PID）、删这台的临时指令，
    不停保活、不清 `/tmp/labmon`、不恢复看门狗（那些属于旧容器）。工作台也不在这台上重新拉起 worker（`pool.relaunch_ok`：组内探测要晚于 worker 状态、认得出还是借来时那个容器）。
  - 主人回来、关了入池、收回之后这台休息 3 小时（`POOL_REST_S`），之内不再借。
  - 还掉以后（主机清单写了 `borrow_returned`，或换了容器）这台目录里还剩的池清单登记（借着时没搬成的、已跑完的）回池里待放；刚还的那一轮快照里的登记还是还之前读的，照收，同一轮放、借看的是收完的样子（#80）。
- **放**（`pool._place`）：要放的清单有三种：池里待放的（队首没被依赖挡住、清单与项目没暂停、项目主人是池成员）、要还的池主机上还有没跑的行的、在池主机上队首因资源等满 10 分钟（`POOL_WAIT_S`）的。
  按 worker 的 `fair_key` 同一口径排先后（人的用量、优先、用量 ÷ 权重，再按登记时刻），要还的主机上的排最前。候选是借着、worker 在写状态、没在要还、主人没回来的池主机，这个项目已有车道的那台优先。
  交给池之前在别的主机上放行、还没收尾的那一格（状态目录的 `current`，worker 的 `run_elsewhere` 认）在那台跑完之前，这条清单放到哪台都一行开不了：worker 的 `pool_heads` 给它记 `elsewhere`（队首取后面那行），看板不放、不为它借，原因写「X 还在 某台 上跑（交给池之前在那台放行的），跑完再放」；
  已放到池主机上的（等待项带 `elsewhere`）回池里等，不当“等满 10 分钟”挪到别的池主机。等它的 `after=` 原因照它实际在哪写（在那台跑着），不写“在算力池里等着放到某台”（#80）。
  放不放得下问目标 worker 的 `fit --list --json`（一次判几台，判断与真放行同一份 `place`），放得下就搬登记（`serve.reg_move`：搬家由 worker 完成，在跑的那一格由原主机跑完；带 `--expect-from` 原来那台，worker 在登记锁里核对它还登记着，会话这期间撤回、搬走的不再登记）；要还的主机上的放不下就回池里待放。
  节流：每台每轮最多放一条，每轮最多问 4 次 `fit`，同一（清单, 候选主机）5 分钟内不重判（只缓存在内存里）；没问过的清单先拿预算，过期的重问排在后面。池清单队首的依赖由 worker 判（状态的 `pool_heads`），看板不另算。
  池那个 worker 目录下各台的 worker 都读池目录、各写一份 `pool_heads`（每 60 秒读一次），看板逐条取：读得到清单的优先，再取读得最晚的那台的（#86：以前整份取状态最新的那台，它刚好还没读到、读不到时，别处读到的也丢了，判成没有还要跑的行，池一条不放）。
  哪一份里都没有的写「还没有在跑的 worker 读到这条清单」；清单里的行都跑完了的写明跑完了（不用了就 `labmon worker rm pool` 撤掉，往清单里加了行会接着放），不算在等、项目车道不写在等，抽屉里收在「池里跑完的清单」。
  放到哪台、搬到哪台、回池里都不叫醒实验会话（#88）：只记 `kind=pool` 的事件，`labmon records` 与项目页时间线看得到，`wait --job` 按快照车道认任务；
  在池里等满 2 小时只给会话报 `pool_wait:<项目>`，每个项目一条、列出在等的各条清单，别的清单跟着等满、清单回池重新计时不另报。
  搬成的这一轮写出的全局快照 `regs` 就照搬后的样子改好（`pool._shift`：原处去掉、新处加上），登记变了的项目当场重采（`serve.Overview.wake_moved`），会话收到「放到某台」时项目页的车道、「主机」、时间线与 `wait --job` 已跟到那台（#78；以前要再等一轮全局采集加一个项目采集间隔，约 3 分钟）。放过去以后车道、在跑与跑完的任务、用量记录都按那台算，和别的主机一样；还掉以后清单回池里，跑完的照样在池车道上。
- **借**（`pool.want_borrow`）：还有放不下、知道要多少资源的，平台操作格空着时，一轮最多借一台：入池、在时段内、没借着、没关机、不在休息期、1 小时内没借不成过；
  最近一次组内探测新鲜（2 个探测间隔内），GPU 上除保活外没有进程（对方轻用不借，比手动借严）、`can_borrow` 为真；主人最近一次有实验已过 `guard_idle_min`；
  截止（时段结束与租期前 1 小时取早）离现在至少 2 小时；卡数够、单卡显存装得下队首（清单写的提示值才比；按历史估的超过整卡时 worker 按整卡算，空卡就借）；这台目录里没有留着别的清单登记（以前手动借时留下的，拉起 worker 就会接着跑它们，要会话先撤掉；池自己放过去的不算，#80）。几台都行时挑卡数最贴的、单卡显存最贴的、空闲最久的。
  动作是 `fleetops.start("borrow", pool=True)`：后台跑、占平台操作那一格，`borrow.begin(pool=True)` 写 `borrow_pool = true`（不写 `borrow_by`，按人统计记在「算力池」名下），guest 指令带 `keep.pool`；探测之后、写主机清单之前在锁里按最新配置再核一次入池与时段（这期间持有人关了就不借）。
  借不成的这台 1 小时内不再借，每台每天通知管理员一次。手动借与池借互斥：池借着的不能手动借，手动借着的池跳过。
- **收回**（`pool.reclaim`，`POST /api/pool/reclaim`）：持有人本人在「我的账号 → 我的服务器」点，或能做平台操作的管理员在组内服务器抽屉、主机页点「收回」。
  按各清单的停法停下池任务（`request_return(now=True)`：停下的重新排队、不记失败），这台上的清单登记回池里，下一轮放到别处；这台休息 3 小时。
- **池借来的主机对实验会话**：不发 `borrow:`、`borrow_due:`、`borrow_back:`、`borrow_idle` 唤醒，不报 `borrow_cut`；还掉以后池的清单（带停法）看板搬回池里，不报 `returned_unfinished`，
  借给池之前就登记在上面的旧清单（停法没写或 `boundary`）池不收，照报 `returned_unfinished` 叫会话自己搬（#88）；`offers` 不给挪法建议（落点由看板定），
  项目「管理」抽屉的「换到其他主机」不列它，`/reg/move` 与 `labmon worker add <池借的主机>` 都拒，提示交给池。
- **页面**：组内服务器卡片与抽屉、「我的服务器」标「算力池借着」或「算力池借着，要还了」，休息期写「入池，休息到 HH:MM（…）」；借着时有红框「收回」，没有手动借的「跑完就还」「现在还」。
  主机短名写「池 持有人」，借用那一句写清为什么借、什么时候还。
- **概况（#76）**：组内服务器页的摘要行有一项「算力池」：`N 台入池（时段内 M，自用 S）· 借着 K（J 要还）· W 条在等`（入池的自用主机算进 N、M，`自用 S` 有才写；悬停另写自用主机跑着几条池清单），没有入池的写「没有服务器入池」（有清单在等时接上条数）；点它打开抽屉 `#/fleet/pool`。
  抽屉的「服务器」一节每台组内服务器一行，入池的自用主机（还跑着池放的清单的也算）同样一行（#79），借着的在前、入池的其次、没入池的最后：使用人（点开这台的抽屉）、id 与资源池、入池那一句与时段（与单台抽屉「算力池」那一行、「我的服务器」同一个 `lendSay`）；
  持有人本人或能做平台操作的管理员（`lendCan`）本行有「入池设置」，借着的有「收回」，不能做平台操作的管理员在节标题旁写为什么没有按钮。
  「池里等着的清单」一节是全局快照 `pool.lists` 一条一行：项目（点开项目页）、目录与清单、在池里还是在哪台上、在池里的等了多久、为什么还没放（没有原因的是这一轮正放出去）；行都跑完了的不算在等（摘要行的 `W` 不算它），收在后面「池里跑完的清单」一节（#86）。
  只读这两份数据，不另加字段与接口；普通用户看不到组内服务器页（`users.view` 不给 `fleet` 与 `pool`），持有人照旧在「我的账号 → 我的服务器」管自己的。

### 自用主机入池（#79）

自用主机（`[[hosts]]`，自己的 worker 一直在跑）也能入池：池里的清单不用借、直接放上来，和主人自己的清单一起按 worker 现有的放行顺序（按人的公平份额，[scheduler.md](scheduler.md)）排，看板不另设优先。

- **入池**：`[[hosts]]` 块里同样的 `lend`、`lend_hours`（`fleet.conf` 用同一条校验 `fleet._lend_check`）；持有人是 `fleet.host_holder`（`platform_holder`），没有持有人的只有管理员能开。开关、时段、代开的规则与组内服务器一样，都经 `pool.set_lend`；
  「我的账号 → 我的服务器」把自用主机也列进来（标「自用」），主机页多一张「算力池」小卡，组内页的自用主机卡片标「入池」、抽屉有「算力池」那一行。
  能入池的（`pool._selfs`、`pool._self_bar`）：在用、不是借来或换来的、不是看板本机或回环（`config.share_host`：池里是组里别人的清单，跑在这台的系统账号下）、worker 目录与池同一个（`config.pool_home`）。每台自用主机各有自己的开关与时段；看板开出来的自用主机（恢复已归还的那块、照抄出新的都算）一律不入池、不沿用上一台的，要入池由持有人手动开（`config.add_mine_host`，维护者 11-18 定）。关机归还的那台自动不再放池清单，上面池放的、没跑完的搬走（下面「搬走」）。
- **池放的登记带标记**：看板把池清单搬到池以外的主机时 `worker add --pool`（`serve.reg_move` 的 `pool`），登记文件里记 `pool: 1`，进状态的 `queues[].pool` 与全局快照 `regs`。自用主机上哪些是池放的只认它，主人自己的清单没有；
  会话自己 `worker add <自用主机>` 同一条清单会重写登记、标记随之去掉，就是钉在那台。池放的清单 `offers` 不给挪法建议（worker 的 `proj_lanes` 跳过）。撤回照旧 `labmon worker rm pool`（`pool.locate` 认标记）。
- **放**：候选是借着的池主机加上此刻在池里（入池、在时段内、不在收回后的休息期）、worker 在写状态的自用主机，按空卡数排，同样空的自用主机在前。池清单在自用主机上队首因资源等满 `POOL_WAIT_S` 同样挪走；队首那一格还在别的主机上跑的（#80 的 `elsewhere`）同样不往这里放、已放上来的回池里等它跑完。都放不下才去借组内服务器。
- **搬走**：自用主机关了入池、出了时段、在休息期、不再能入池或归还了：这台上池放的清单按「要还的主机上的」去放，放不下回池里；在跑的那一格由这台跑完（worker 的 `run_elsewhere`）。主人回来、空闲就还、换容器这几条只对借来的主机，自用主机不适用。
- **收回**：先把池放的清单搬回池里，再对这些清单在跑的项目在这台下 `pause --now --once`（按清单的停法停、重新排队，停完自动删）；同一项目在这台还有主人自己清单的不停，只搬、在跑的跑完。之后 3 小时不往这台放。

## 平台会话

平台账号是全组共用的，同一账号只保留一个登录：看板登录会把网页上正在用的人顶下线，网页上有人登录也会让看板的令牌失效。
所以令牌连着几次操作复用（页面写着“已登录平台”），失效就停在那一步、要求重新输验证码；不后台轮询。
令牌另存一份秘密（与平台密码同一处：macOS 钥匙串的 `labmon-platform-token`，Linux `~/.config/labmon/secrets/platform-token/<账号>`，[deploy.md「平台密码」](deploy.md#平台密码)），看板服务重启后接着用，到期（48 小时）或点“退出”就删掉。
自用主机的续租也是这条流程（主机页上的“续租”与这里的批量续租），同一个登录。
平台操作只给管理员；从公网入口来的还要这个管理员账号开了公网平台操作（见 [api.md](api.md#两个入口)），一次只做一件，步骤之间像人点按钮一样隔几秒，出错不自动重试。
进度写在 `op.json`（记着看板进程号）：做到一半看板服务重启了，页面上标成停在那一步，平台与服务器此刻的状态要到平台上看。

## 命令行

```bash
labmon fleet                    # 各台现状
labmon fleet status 29-15158   # 只看一台，列出各组负载、父进程链与目录
labmon fleet probe 29-15158    # 立即探一次再列出（与看板共用状态，有文件锁）
labmon fleet boot [29-15158]   # 开机参数；给了 id 就连克隆配置一起列出
labmon fleet import 29-15158 carol.json   # 导入网页作业详情里复制的 Json 文件
labmon borrow 27-15152 --until "明天 18:30" --for a1 [--away]   # 借来用（--away：对方说好约定前不用，不给这人留余量）（--until 也认 11-08 18:30、21:45（今天）、+90m、+6h）；不给参数列出在借的
labmon host return 27-15152 [--now]     # 要还：跑完自动还（--now 先按停法停下正在跑的）
labmon host restore 27-15152            # 撤销跑完就还（还掉之前、约定时间之前）
```
