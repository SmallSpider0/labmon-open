# 跨项目调度：设计与依据

目标是本机所有科研项目共用实验室服务器时，由 labmon 统一决定资源，各项目只管自己跑什么。
现在的规则（准入、公平份额、独占、借来的主机、推演、临时指令、单元申请）只在 [worker.md](worker.md) 写全；这里写为什么这样设计、依据与分期。

## 分工

- **labmon 管资源**：在哪台主机、哪张卡上跑，能占多少内存，什么时候开始、什么时候停，GPU 保活，项目之间怎么轮。
- **项目管内容**：跑哪些单元、按什么顺序、怎么续跑、写什么回执与证据。

两种接入方式共用同一个资源池与同一套准入规则：

| 方式 | 适合 | 谁启动进程 |
|---|---|---|
| 任务清单（worker 队列） | A1 这类一行一个命令的实验 | worker |
| 单元申请（`slot`） | 示例项目 这类自带监督进程、单元之间有依赖的项目 | 项目自己，每个单元启动前先申请 |

整次运行打包登记一个固定范围（“托管运行”）的做法不采用：两层闸门各看一半，范围本身又是写死的数。

## 依据

- 单卡可以容纳多个轻量任务；显存空余并不代表容器内存与 CPU 同样充足。
- 容器内存可能在启动后上涨，准入需要按历史峰值预留并读取 cgroup 的实际限额。
- GPU 工具可能报告宿主机 PID，worker 通过进程元数据映射回容器 PID。
- 容器配额可能不同于宿主机资源总量；重建容器后必须重新测量并恢复 worker。

## 资源模型

每台主机每轮现读，不写进配置：

- 各卡：UUID、总显存、已用显存、利用率。
- 内存：cgroup 上限与工作集（`usage − total_inactive_file`；v2 用 `memory.max`、`memory.current`、`inactive_file`），只显示；收不回的 `anon`（用量 − 文件页：v1 `usage − total_active_file − total_inactive_file`，v2 `memory.current − active_file − inactive_file`；含 shmem 与内核占用，不算页缓存），放行、内存闸门、借来的主机上算对方用量与快撞上限都用它；以及 cgroup 的 OOM 计数。
- 核数：cgroup 配额（v2 用 `cpu.max`），向下取整是 CPU 记账的上限，读不到时不记 CPU；被限流的周期（`cpu.stat`）。
- 读写：每个任务的 `rchar`、`wchar`；共享盘每次读写的执行时间（mountstats）、本地盘忙碌（diskstats）、有 PSI 时的压力（[worker.md「CPU 与读写」](worker.md#cpu-与读写)）。
- 磁盘：`data_root` 的余量；容器根盘开机以来的新写入（`info.rootfs` 与本地盘扫描，续租会清空，只显示与提醒，准入不看）。
- 容器启动时间。

CPU 像内存一样记账（硬上限是配额的 100%，估计核数 `cpus=` → 同类峰值 ×1.1 → 1 核），页缓存不算 labmon 之外的内存（Issue #4 方案 A 的期 2，Issue #6）。
读写不设闸门：共享盘慢时只让我们自己的扫描与拷贝让路、记“读写拥塞嫌疑”，`io=` 只记录（期 3 才可能用）。

## 设计要点（为什么这样）

- **按峰值记账、整个生命期不变**：任务刚起来时内存还没涨上去，照样按峰值占位，防止 运行期间的内存突涨把容器撑爆。
- **内存闸门只停放行、不杀任务**：等待资源的代价通常小于任务被 cgroup 终止后重跑。
- **真放行与推演同一份 `place`**：输入是资源快照；推演在模拟的时间轴上维护同样的快照，显存记账同样按估计值。两份规则必然漂移，页面上的预计时间就会和真放行对不上。
- **公平份额**（参考 Slurm 的 fair-share 与 HTCondor 的用户优先级；用户定的缺省：按衰减的 GPU 用时、跨主机算，半衰期 1 天、等待上限 30 分钟，不抢占）：
  跨主机比总用量，一个项目在 29 上用得多，在别的主机上就让别的项目先。卡数按显存份额记，几个小任务分着一张卡时不按整卡记。
  设置放用户级主机清单 `[sched]`，不放项目的 `monitor.toml`：项目不能自己给自己提优先级。
- **屏障只拦会耽误它的**：屏障不排到权重前面（单卡跑长任务时轮到的总是等了一整个任务的那个，权重就不起作用了），也不让整台主机停下等它，
  只要求后面的请求预计在它放行前跑完才放（回填）。放不下的请求不成屏障，否则它一等满 30 分钟就一直挡着别人。
  等待时间不算被临时指令挡住的那段，不然 pause 半小时一 resume，队首立刻成屏障、别的项目全让位。
- **独占**（11-04 用户要求，开销评估、计时测量用）：只为 labmon 的任务留卡——它们会跑完，留着才腾得空；labmon 之外的进程占着时不留、也不算卡在资源上，
  否则借来时对方的小进程常驻，独占任务一直留着卡，整台主机的任务都堵住。放行前与运行中作废用同一个判定，整机独占放行前也看 labmon 之外的 CPU 连着两轮占 1 核以上（一轮的尖峰不算），不然照样放行、20 秒后作废，反复空转。
  每个任务的历史记录都写明运行期间同卡、同机有没有别的任务，计时结果可以据此核对。
- **借来的主机**（为以后组内服务器多人共用打基础，准入参考 HTCondor 的放行条件；用户 11-06 定）：对方轻用时也可借；给对方留的量按对方历史用量推荐，不用固定数；
  对方回来用时不停正在跑的——这一格跑完再说，停了白跑，线下和对方商量；真撞内存上限时先牺牲我们的任务（`oom_score_adj`），保住对方的体验；
  被挤掉的不记失败、重新排队。借卡的抽象按共享的概念来做（让路、预留、按卡），“留卡给对方”按卡，只对多卡有意义。
- **推演**：各页面上排队任务的预计开始、结束不再由各项目看板各算一套，统一取 worker 的推演。超过预计的运行中任务剩余按已跑的 20% 估，否则后面任务的预计开始永远是“现在”，每轮往后滑。
  时长不明的任务排上后不知道何时结束，要等它腾资源的任务也排不上（不能当它 0 分钟就跑完，否则后面的全挤在同一刻）。
- **预计时长按同类历史折算**：清单估时常常系统性偏高或偏低，按同类 实际/估时 的中位数折算；没有同类时按本项目近期的加权比值；只认同型号 GPU、同卡没别的任务时的记录（分时共用一张卡时速度约减半）。
- **单元申请走容器本地文件**（`/tmp/labmon/slots/`）：不走 NFS，没有时钟偏差。申请方 `exec` 原命令，进程号与退出码不变，进程一退出名额就收回，不需要显式释放。
- **容器重启后自动拉起**：容器里配自启没用，由本机看板拉起；监督进程可以登记成一条 `gpus=0` 的清单任务，容器重启后由 worker 续跑。
- **页面上能看、能改**（排位解释参考 Slurm 的 `sprio`，份额对比参考 YARN 的调度页，平均等待参考 ClearML）：等待表逐条解释为什么排在这里；调度卡上改权重与优先；手动插队暂不做。

以后：真需要时再做抢占（只停标了可续跑、已跑满最短时长的任务，先 SIGTERM 再等宽限期，Slurm `GraceTime` 的做法）；页面上的冲突与建议（如某项目长期被让位）等有了实际使用再看要什么。

## 分期

1. **观察**（11-04）：worker 现读主机容量、记每个任务的用量与历史；工作台（总览、主机页、项目页）；容器启动时间与撞上限计数。只读，不改任何项目的跑法。清单任务的 `exclusive=gpu|host`。
2. **准入与重启**（11-04）：按记账放行、内存闸门、tag 限额、单元申请接口、各队列的停法、容器重启后自动拉起；事件（`events.jsonl`），工作台列出。
3. **临时指令**（11-04）：`pause`、`resume`、`focus`、`unfocus`、`drain`、`undrain`，工作台列出生效中的指令与撤销命令。
4. **借来的主机**（11-06）：`guest` 指令、给对方留的量、被挤掉重排、作废经 `void:` 报。
5. **推演**（11-07）：排队任务的预计开始、结束统一取 worker 的 `plan`；占用时间线。
6. **公平份额与调度设置**（11-07）：用量 ÷ 权重排序、屏障与回填、跨主机用量、`[sched]`。
7. **看得见、页面上能改**（11-07）：排位 `pos`、等多久 `wait`、调度卡、`POST /sched/…`。
8. **示例项目 接入**：示例项目 下次开跑前由 示例项目 自己的会话改监督进程（单元命令加前缀，删掉自带的闸门、选卡、重型锁与保活租约）。

## 算力池离线试算（#244）

维护者可运行 `python3 -m labmon.pool < examples/pool-shadow.json` 回放两机各一张卡的试点场景，或在 Python 中调用 `labmon.pool.plan(snapshot)`。输出为 JSON，`mode` 恒为 `shadow`。入口不读取主机清单、登录账号或共享盘，也不执行作业。看板用户接口须由调用方另做授权和最小投影。

快照由受信调用方准备。下表的时刻均为 epoch 秒，设备用真实 GPU UUID。一次试点使用同类整卡，适配性以授权设备清单为准。同一物理机上的两个容器/worker 必须提供不同的执行节点 ID，不能合并为一个节点。输入方须确认多个执行节点的 CPU 与内存预算不重复。物理机未核实可用 `null`，该节点仅参与独立单卡试算。准备快照时须排除未经批准的环境及失去授权的项目，`eligible_nodes` 必须使用每个项目实际获准的节点及设备列表。队首、暂停、依赖、环境和数据是否就绪由输入方核实。

| 输入 | 必填字段及口径 | 可选字段 |
|---|---|---|
| 快照 | `now`、`nodes`、`jobs` | `attempts` 缺省空 |
| 节点 | `node`、`physical_host`、`model`、`state`（`ready`、`paused`、`offline`、`borrowed`）、`observed_at`；`cpu_cores` 和 `ram_gib` 是扣除实际运行负载后的可用量，未启动承诺和本次观测以来开跑的作业由试算另扣；`ram_limit_gib` 为原始上限，用于计算内存余量；`cards` 每项为 `uuid`、`vram_mb`、`free_mb`、`idle`（整卡此刻未被任何进程占用） | `deadline` 节点最迟可用时刻 |
| 作业 | `job`（稳定的队首 ID）、`project`、`account`（可信、稳定的账户 ID）、`gpus`（正整数）、`since`（队首可运行起算）、`vram_gib`（每张）、`ram_gib`、`cpu_cores`、`eligible_nodes`（节点 ID → 获准的 UUID 列表） | `paused`、`focus_until`（经管理员授权的优先到期）、`duration_min`、`deadline` |
| 尝试 | `attempt_id`、`job`、`account`、`project`、`node`、`gpus`（UUID 数组）；已承诺用 `reserved_at`，已启动用 `t0`，跑完加 `t1`，未启动撤销加 `released_at`；活跃尝试还需 `cpu_cores`、`ram_gib` | 同一尝试的多条回执共享相同身份字段，可补充阶段时刻 |

先把仍在跑和已承诺的卡都算给账户。允许的限时优先先排，其余按账户当前占用从少到多，同档按可运行的队首先后和稳定作业 ID。每个候选只从单个合格节点取整卡，使用现有 `place` 校验资源，使用 `acct_job` 扣这一轮假设分配的 CPU／内存并重新比较账户占用。候选节点优先填剩余空卡少的，尽量给别的节点保留连续可用的多卡组。碰到物理卡或环境不足的作业，其他独立任务照常匹配。本轮只比较此刻能不能放，截止使用已有 `fits_before` 的估时余量。池内跨机成组、抢占、预留未来时刻的屏障由后续独立设计决定。

管理员一次性真卡试点（#252）用现测单卡节点快照调用同一个 `pool.plan`。只把两项已获成员/项目授权的固定算子匹配到两台节点。同机双卡申请只用于验证等待原因。实际起进程前由远端 worker 再核节点、设备、保活与本机资源，流程见 [管理员固定算子试点](pool-execution.md#管理员固定算子试点252)。

- `capacity` 给 `total`（不含借来节点，暂停和离线仍算已登记）、`free`（状态新鲜且接单的整张空卡，已扣活跃尝试）和 `max_same_node_free`。前两项为全池统计，最后一项按单执行节点，物理归属未知节点最多贡献 1。三项是试算前的观测值，与某个项目能否使用或任务是否放得下分开。
- `nodes` 给 `node`、`physical_host`、`model`、`total`、`free`、`state`，过期用现有 worker 过期阈值，标 `offline`。
- `assignments` 每项有 `job/account/project/gpus/node/devices`；`waiting` 每项有 `job/account/project/gpus/reason/text`。常见原因 `same_node`（需要 N 张同机空闲卡）、`busy`（等下一张空卡）、`vram`、`ram`、`cpu`、`cut`、`paused`、`offline`、`ineligible`、`active`（已在跑或承诺）。
- `usage` 按账户给 `active_cards`（实际在跑与未启动承诺的卡数）、`card_seconds`（从提供的可信回执算出的实际卡秒）。卡秒按 `attempt_id` 合并同一身份的乱序重发，未启动承诺不记卡秒，历史不改变当前占用排序。调用方决定提供哪些历史，结果不是持久账本。设备别名重复、两个活跃尝试占同一卡、同一尝试身份或时刻冲突使整个输入失败，命令行退出 2。
