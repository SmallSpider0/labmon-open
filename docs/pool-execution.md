# 算力池供给与执行

算力池采用同实验室成员互信模型，管理共享服务器的供给与调度。实验按 `skills/lab-experiments/` 和已有个人服务器、共享盘约定执行；本阶段只支持已有个人服务器和共享盘的用户，不另建文件传输、环境安装或无服务器接入流程。个人服务器已供给到池里或暂时离线不改变拥有关系。

#245 的离线协议保留为实现参考；现场试点记录在 #247。#251 的独立 OS 身份与宿主强隔离方向已关闭，不是本阶段上线前置。

## 管理员固定算子试点（#252）

- 在看板内网用管理员令牌。先确认两位持有人同意，核实两台各只有一张同意提供给算力池的整卡、租期覆盖窗口、卡上没有实验。持有人的确认只授权固定算子。组内服务器保持原归属和借用状态。
- 用已登记的两位试点账号与各自拥有的试点项目。现有常驻 worker 必须为当前已部署 main 版本，试点占用期间共用它的本机接单锁。没有常驻 worker 的已知组内服务器会经正常受信 SSH 一次性启动固定任务的 worker。两个入口都查主备租约、实卡 UUID、容器代际和现场进程。
- 使用隔离的容器本地目录运行仓库中的固定 CUDA 矩阵乘法。worker 只传算子用的设备、环境变量和目录。容器内的系统身份与共享盘挂载仍采用组内互信。普通成员的任意清单与试点入口独立。

```sh
labmon pool supply A GPU-uuid-a --holder 甲 --account member-a --project pilot-a --until +15m --agreed
labmon pool supply B GPU-uuid-b --holder 乙 --account member-b --project pilot-b --until +15m --agreed
labmon pool run A B
```

用实际节点编号、持有人名字和完整 GPU UUID 替换示例。两条批准命令只登记授权，最长 30 分钟。运行命令用 `pool.plan` 对两个单卡实验放行，检查一项双卡申请因需要同一执行节点被拒绝。结果列出每个节点的设备、尝试、账号和 CUDA 算子结果，以及两节点算子的观测时间交集。核对 UUID、算子成功、保活状态恢复和两次尝试的结束回执。停掉原保活后，执行端最多等 8 秒让已确认的旧 PID 从驱动查询中退出。若看到新进程立即拒绝并保留原因。回执的 keepalive 单列 restored（已恢复）、busy（当前已有其他 GPU 进程，等待自然腾空）或 failed（恢复失败）；不覆盖任务原因。若仅剩保活待恢复，使用 status 续查，卡自然腾空后恢复原保活再释放本轮授权。普通 worker、平台操作和借用继续各走原入口，池试点期间阻止资源转让及预备续租。试点任务持续约 25 秒，启动到收尾有两分钟量级的硬截止。

未运行的授权可用 `labmon pool revoke A` 撤回，到期也会自动失效。已认领的固定任务按自己的截止退出。失联或未收到结束回执时用 `labmon pool status A` 核对同一次尝试，避免复投。核对接单锁、容器代际和原回执后解除授权。容器重启或回执损坏时管理员先依据现场进程、GPU 与本地目录核清，再处理状态。固定任务的日志和回执保存在容器本地 `/tmp/labmon/pool-trials/<尝试编号>/`，只供管理员验收；保存所需证据后可清理这一个已完成的目录。

## 离线协调协议参考（#245）

- 试算候选的账号、项目、任务、节点与设备可用于构造承诺提案。受信适配器重新核实账号授权、队首、工作区、专用节点与代际后才能调用 `reserve`。试算字段不能直接用于签发。
- `Grant` 绑定账号、项目、队首、清单及其 .env 的指纹、尝试 ID、节点、物理机、执行代际、设备、CPU、内存和到期时间。节点状态从受信库存读取，租户不能提供或设置隔离验收状态。节点物理机和代际在真实现场核实。
- 账本在受信协调者的私有本地磁盘目录。仅协调者可写，租户工作区和共享盘不能访问。每节点 launcher 凭据独立，生产适配器须认证传输和服务端并保管凭据。离线库无 HTTP、CLI、部署或进程执行入口。
- `launch` 在启动前持久化未知状态，再核对承诺，调用受信 backend 的 `matches` 和 `start`。backend 要在启动边界继续核对授权、工作区指纹与设备代际，并用同一次尝试的身份清理进程和设备。SQLite 写事务串行化启动与释放，backend 操作须有界且不得回调协调者。
- 启动结果未知时照常占用整组设备，避免重复启动。已认领的承诺只能由同节点、同代际 launcher 证实尝试停止、资源可重用后释放。过期且未认领的承诺可撤销。若节点代际已消失，保持占用并人工核对，当前没有自动代际迁移。
- `request_stop` 只接受信账号适配器给出的身份。launcher 在核对时调用 backend 的 `stop` 并确认 `cleaned`。结束回执可重发，已用尝试 ID 不可重领。

## 成员清单日常派单（#254）

日常派单默认关闭。管理员在内网用 `labmon pool supply-daily <节点> <GPU UUID...> --holder <持有人> --until <时间> --agreed` 批准一组整卡，最长一天并不得晚于容器租期。核对成员、项目工作区、节点与保活后，用 `labmon pool dispatch on` 开启。关闭用 `labmon pool dispatch off`，已经认领的任务继续核对。用 `labmon pool revoke <节点>` 撤回，已运行的尝试继续收尾，节点收尾前仍与借用及平台操作互斥。

成员在项目内登记已经准备好的清单。清单仍由来源 worker 按既有依赖规则准备任务，GPU 行的资源请求随状态发布给池；池只分配节点和整卡，不自行解析清单推进实验。`after` / `afterany` 沿原 worker 判断，`needs` 在目标节点走原本地缓存准备。CPU 行仍由来源 worker 使用原 CPU/内存准入，不占池 GPU；供给闸门仅允许已标为池清单的 CPU 行，不开放普通专属 GPU 任务。同一节点一次执行一条池尝试，可使用该节点的多张整卡；显式跨节点 gang 仍用原 worker 的明确节点安排，不把跨节点卡拼成同机 DDP。预计时长取 worker 原估计，无估计时说明无法核对供给期限。清单和 `.env` 沿既有校验，代码与共享环境仍由实验会话准备，不另建环境服务。

使用 `labmon pool list` 查状态，已核实的队首可用 `labmon wait --job <项目>/<任务>` 监听。用 `labmon pool stop <登记编号> <尝试编号>` 请求停止本人当前尝试，管理员可代管。到供给截止，执行端按本次进程组停止；终态需在进程清理及 GPU 核实后写回。断线或代际不符时保留占用，避免重放起跑。若账本一直显示未知，管理员应在节点核对原尝试、进程组和 GPU，确认清理前不得重新供给。资源分配与清理回执留在执行容器的 labmon 本地状态目录；任务使用原 `QUEUE_STATE`、`QUEUE_LOGS` 和 `.env`，完成标记、日志及实验结果仍在项目约定位置，不另存冻结环境。正常任务失败后由原 worker 决定后续依赖；启动前失败和主动停止保留人工处理入口。

## 项目资源与供给闸门（#267）

实验以项目为上下文。先运行 `labmon project resources --project <id>` 查看项目主人的资源；管理员代管也不会把管理员自己的服务器加入候选。一个项目可同时使用自己的池外专属服务器与算力池，每条清单只选一个目的地：

```sh
labmon project submit jobs/train.txt --destination pool --request-id train-01
labmon project submit jobs/local.txt --destination 29 --root /共享盘/projects/项目 --request-id local-01
```

缺省项目取当前目录的 `monitor.toml`。断线后保持目的地、路径与 `request-id` 不变重试；改变资源或清单要用新编号。池成员资格按项目主人核对，工作区仍由管理员经 `labmon pool bind` 绑定。客户端登记资源目的地；原 worker 发布已就绪资源请求，看板按同一项目与清单身份分配节点；目标 worker 使用原准备、放行与收尾函数执行。池账本仅保存分配及占用，不用另一份完成历史推进清单。配置同步、文件准备与运行回执是三件事；`project push/pull` 只同步配置，不会上传代码、环境或数据。

空闲清单切换时，执行端在原登记锁内交接，保留一个带池目的地的来源登记；池待派单期间也保留清单路由标记，普通 `worker add` 不能抢回。已有 `current` 或池尝试未清理时拒绝切换。清单跑完后可在项目记录中「解除登记」，然后按会话的清单安排继续使用。清单文件已删除或改名时仍可解除旧登记；原尝试未收尾或还有 `current` 时继续拒绝，不能借文件缺失跳过占用检查。`.done`/`.failed` 标记随清单交接，避免已结束任务重跑；`QUEUE_STATE` 必须位于项目目录内。不同工作区不自动搬运文件或迁移进程。池提交处于 `preparing` 时表示交接尚未得到确认，可用原编号重试或撤回，不表示任务已开跑。

服务器日常供给先保存意图，再在共享 worker 目录写持久闸门。普通队列、单次 slot 申请与推演都读同一闸门。已运行任务照常收尾，供给在确认空闲后才变为 `ready`。服务器状态必须声明 `pool_supply_gate`；旧 worker 要先升级，不能只升级看板就宣称互斥生效。

供给状态为 `preparing`（关闭专属通道并等收尾）、`ready`（可供池使用）、`releasing`（收回或到期，等清理）、`released`（收到解封回执）。关闭派单只停止分配新任务，不解除供给闸门。掉线、状态损坏、换容器或清理回执不明时保持阻挡；不因本地时钟到期自行解封。收回需先确认全部认领/运行尝试结束，再由执行端释放闸门。恢复后本人专属通道才可再接单。

本阶段只支持已持有个人服务器、沿用现有共享盘的用户。成员资格按账号关联人员与服务器持有人核对，不因自己的服务器已入池或暂时掉线取消；借入服务器不计为个人服务器。管理员可以管理池，但作为池用户也遵守这一资格。

代码、环境、数据和结果按 `skills/lab-experiments/` 的共享目录、tar/SSH 与本地缓存约定处理。清单与训练命令由实验会话准备，项目入口只登记已有清单并选择资源；不新增文件传输、环境管理或强制验证任务。

实验会话按 Skill 直接经 SSH/tar 更新共享目录中的代码，再登记清单；任务执行这些文件。提交不上传代码。沿用现有清单与同名 `.env` 核对，本次不扩展源码快照、源码哈希或服务器版本管理。


### 采集、迁移与回退（#267）

来源请求、供给库存和在途回执随工作台原采集批次读取。已有个人主机复用该连接；没有常驻 worker 的组内供给节点加入同一采集批次，但不加入普通个人主机清单。池协调器仍定期做本地分配判断，不为每条清单或每次尝试另起常态 SSH 轮询；启动和停止发送即时控制，重复停止只在尚未确认时重试。断连或超过 `STALE_S` 的观测不能当作空闲，结果未明保留占用。观测更新速度随工作台采集间隔，额外受一轮采集耗时影响；不宣称每 5 秒都有新的远端结果。

升级先关闭新派单，原在途任务由旧执行进程收尾。升级看板与 worker 后，开启派单会先检查旧在途是否清理，再逐条迁移待派登记：将已核实旧结果写回原队列标记、保留实验文件、标记新的来源登记协议。中断后只重做未完成项；来源 worker 必须在实际状态中声明支持准备请求，不能只凭共享脚本文件更新就放行。迁移失败保持新派单关闭，处理原因后再开启。

回退先关新派单并等在途清理，解除池路由；供给服务器先收回并确认闸门释放，再沿原 worker add 恢复明确的专属登记。不能直接覆盖旧账本或在未核清时启动第二套派单。旧历史仍供查询，旧待派清单需完成迁移，不能新旧执行链同时推进。部署与回退均由总控统一组织。

## 资源页面与管理（#269）

算力池页只观察共享服务器、实际占卡和需要处理的异常；实验仍从项目提交与查看。页面沿用服务器的身份与详情，普通成员仅见获准的资源摘要与本人项目，管理员可查看全池分配。不再提供独立的池实验页。

内网管理员在「管理」抽屉维护已有个人服务器与共享盘的人员账号成员资格、提供服务器、暂停接收新任务和收回服务器。供给从已有采样的整卡名单选择，确认持有人同意并填写截止时间；提交时仍由供给后端重新核实。缺少设备采样时不能凭空填造资源。移出成员前须先处理这人的待位和未收尾任务，不会自动终止实验。管理员始终有管理权限。

暂停派单只影响新任务，资源页继续显示真实运行。准备供给、可接单、收尾中、已收回分别展示；退出须等待实际清理确认，未知状态不能当作空闲。当前分配只说明现在谁在使用哪些卡，不提供尚无推演依据的开跑时间。

执行节点沿用原 worker 的 `$LABMON_CACHE` 与 `$LABMON_SCRATCH` 目录，缓存跨尝试复用；完成记录写回该节点共享 `usage.jsonl`，供原 worker 的依赖与资源估计读取。任务仍使用原池执行的受限环境，`HOME` 是尝试目录；环境文件使用现有共享盘或节点已安装环境的绝对路径，不依赖管理用户的家目录。

`start_before` 只限制新接单；执行端持有本次资源锁后，原 worker 的 needs 缓存准备可跨过这45秒，状态仍是启动中。准备和最终放行继续核对供给到期与停止请求，到期或停止后完成清理才释放占用。启动前重读原主机收到的暂停、drain 等指令；准备期间暂停的任务继续等待，恢复后再放行。

项目有待位或在途池清单时先撤回或等待收尾，再归档。已完成清单归档时沿原撤回流程释放共享目录中的池路由并保留尝试历史；远端未确认释放就不记归档。恢复项目后可重新登记到专属服务器或池。

### 项目内的状态与日志（#268）

项目时间线按清单、任务与启动时刻识别同一次运行，使用池分配的真实节点和 GPU；原队列仍显示准备与依赖情况。运行条右端是最后观测，旧记录只有清理确认时刻时明确标注，不当作预计结束。项目管理在同一记录区提供撤回、停止和尝试详情；在途尝试全部保留，历史展示最近 20 条，日志尾部取原 QUEUE_LOGS。

待位、启动、运行、停止与清理未明均阻止归档、更换主人及删除关联账号。监听读取同一尝试账本，当前池运行不被普通任务旧终态覆盖；未知状态不会凭查询时刻延长运行条。正常任务失败后原 worker 按清单依赖继续，主动停止或启动前失败保留人工处理入口。实验文件、环境和结果继续沿既有 skill 约定管理。

### 页面绑定已有工作目录（#283）

首次使用池时，内网管理员在项目管理的「运行资源」点击「绑定工作目录」，填写现有读盘服务器与共享项目目录；唯一的现有登记会自动预填。沿原绑定接口核对实际路径与重叠，成功后点击「提交清单」选择算力池。公网管理员与普通成员不能绑定；已有绑定的项目成员仍可提交。池节点详情显示供给状态并链接到同一个管理抽屉，公网入口说明权限限制。
